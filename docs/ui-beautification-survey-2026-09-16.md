# 界面与排版美化调研（2026-09-16）

> 纯表现层调研，**不改任何机制、数据与模拟**。全部结论来自
> `scripts/_ui-survey.mjs` 的实测（12 个桌面页 + 5 个手机页）与对
> `css/style.css` / `js/main.js` 的静态普查，不是主观观感。
>
> 结论分三层：**A 设计令牌缺失（系统性，收益最大）**、
> **B 具体布局缺陷（逐个可修）**、**C 观感细节**。

## 0. 一句话结论

这套界面**结构是好的**（FM 风格的战术页/比赛页布局合理，卡片层级清楚），
问题几乎全在**「令牌没有收口」**：设计令牌（`--radius` / `--shadow` / 颜色变量）
已经定义了，但被大量字面值绕过。结果是**全站 34 种字号、164 种颜色、
16 种圆角**——不是设计得差，而是**没有统一的设计语言在执行**。

## A. 设计令牌缺失（系统性）

### A1. 字号：全站 34 种（CSS）+ 9 种（JS 内联）

`css/style.css` 里出现的不同 `font-size` 值：

```
0.55 0.58 0.62 0.65 0.66 0.68 0.70 0.72 0.74 0.75 0.76 0.78 0.80 0.82
0.84 0.85 0.86 0.88 0.90 0.92 0.95 1.00 1.05 1.10 1.15 1.40 1.45 1.55
1.60 1.75 1.80 (+ 9.5px / 10.5px 两处绝对像素)
```

**逐页实测的「一页内字号数」**（探针统计每个可见文本节点）：

| 页面 | 页内不同字号数 | 明细（px） |
|---|---:|---|
| 概览 dashboard | **11** | 11,12,13,14,15,16,17,18,20,22,26 |
| 战术 tactics | **10** | 7,9,10,11,12,13,14,15,16,17 |
| 阵容 squad | **8** | 7,10,12,13,14,15,16,17 |
| 世界赛事 competitions | **7** | 5,8,12,13,14,15,16,17 |
| 转会 transfer | **7** | 7,12,13,14,15,16,17 |

另有 **`js/main.js` 33 处内联 `font-size`**（9 个不同值：0.75/0.78/0.8/0.85/
0.9/0.95/1/1.25/1.35rem），**完全绕过 CSS**。

**小字号已经越界**：`_briefing-layout-probe.mjs` 在比赛屏量到 **50 个元素 < 11px**：

| 元素 | 字号 | 个数 |
|---|---:|---:|
| `.mp-bench-dot`（替补席号码点） | 8.0 | 16 |
| `.form-cell`（最近五场 W/D/L 方块） | 10.88 | 10 |
| `.muted` | 10.4 | 7 |
| `.team-talk-desc` | 10.88 | 5 |
| `.mp-official`（裁判/助理裁判） | 9.5 / 10.5 | 3 |
| `.mp-end-label`（球门端标） | 8.8 | 2 |
| `.fm-sb-live` / `.mp-bench-side` / `.mp-fmm-speed` | 9.92–10.88 | 3 |

**建议**：定义 6 级字号令牌并把现有 43 个值全部归并。

```css
--fs-xs:   11px;   /* 辅助/角标下限，替代 0.55–0.68rem 这一堆 */
--fs-sm:   12px;   /* 次要文本（表格、muted） */
--fs-base: 13px;   /* 正文 */
--fs-md:   14px;   /* 卡片正文/表格主列 */
--fs-lg:   16px;   /* 卡片标题 */
--fs-xl:   20px;   /* 页面主标题 */
```

预计影响：**~450 处 `font-size` 声明**（CSS 34 值 + JS 33 处）收敛到 6 个令牌。

### A2. 颜色：572 处用令牌，480 处硬编码（**164 个不同 hex**）

| 指标 | 数量 |
|---|---:|
| `var(--token)` 引用 | 572 |
| 硬编码 hex | 480（**164 个不同值**） |
| `rgba()` 字面值 | 589 |

问题不是「没用令牌」，而是**存在两套并行调色板**：

| 令牌（项目自有） | 并行的硬编码（Tailwind 风格） |
|---|---|
| `--muted: #8b9bb8` | `#94a3b8`（slate-400，用了 13 次） |
| `--text: #e8eefc` | `#e2e8f0`（slate-200，15 次） |
| `--bad: #f07178` | `#f87171`（red-400，9 次） |
| `--warn: #e6b450` | `#fbbf24`（amber-400，14 次） |
| — | `#93c5fd` 12 次、`#86efac` 12 次、`#fca5a5` 9 次 |

外加**同一颜色两种写法**：`#fff` 33 次 + `#ffffff` 17 次。

**建议**：以现有 26 个令牌为基准，把 164 个 hex 映射到令牌（预计收到 ~40 个），
并统一 `#fff` 写法。

### A3. 圆角 / 阴影 / 间距：令牌定义了但没在用

| 维度 | 现状 | 令牌 |
|---|---|---|
| `border-radius` | **16 个不同值**（2,3,4,5,6,8,9,10,12,18,50%,99px,999px…） | `--radius: 12px` **只被用了 4 次** |
| `box-shadow` | 5 处 `var(--shadow)`，其余 20+ 处 ad-hoc rgba | `--shadow` 存在但基本被绕过 |
| `padding` | 0.65/0.75、0.55/0.7、0.7/0.8、0.9/1、0.55/0.65、0.4/0.5、0.75/0.8… | 无间距标尺 |

**建议**：`--radius-sm/md/lg` 三级 + `--space-1..6` 六档，替换字面值。

## B. 具体布局缺陷（逐个可修，均已实测）

### B1. 桌面开赛前：球场被压成细条，浮在空列中间 ⭐ 观感最差

| 视口 | 球场盒 | 所在列宽 |
|---|---|---|
| 1440×1000 | **175×240** | 585 |
| 1280×800 | **82×112** | — |

成因：宽屏走 grid，开赛前简报占 `min(56vh, 520px)` 后，球场行只剩 ~240 px，
而 `.mp-field` 被改成「高度跟行走、宽度按 2:3 反推」（`css:1594`）。
结果球场缩成一个小方块居中，两侧大片空白。

⚠ 这与刚修的「窄屏简报被压成 2 px」是**同一个病的两个方向**：
窄屏是「球场撑爆容器 → 简报被牺牲」，宽屏是「容器给行高 → 球场被牺牲」。
**修之前必须先定义「简报与球场谁让位」**（交接文档已列为独立议题）。

### B2. 手机顶栏占掉 **25.7%** 屏高

实测 `.topbar` 高度（`_ui-survey.mjs` 的 `chrome` 块）：

| 视口 | 顶栏高 | 占视口 |
|---|---:|---:|
| 桌面 1440×1000 | 96 px | 9.6% |
| **手机 390×844** | **217 px** | **25.7%** |

手机档顶栏（品牌 + 副标题 + 元信息 + 主导航 + 二级标签）比桌面**高 2.26 倍**。
其中 `UI Survey · 英格兰乙级联赛` 在 logo 旁折行，与右侧按钮抢宽度。
二级导航本身 83 px（桌面 71 px），且 `overflow-x: auto` 隐藏滚动条 ——
分组内的标签在手机上要横滑才能看全。

### B3. 手机阵容表：位置列被裁，且双标签冗余

`#squad-table.squad-compact { min-width: 46rem }`（736 px）在 390 px 屏上
必须横向滚动才能看到「位置」列（探针量到 308 个元素越界，
`docScrollW == clientW == 390`，说明在 `.table-wrap{overflow-x:auto}` 内滚动，功能正常但体验差）。

同时**位置列显示两个标签**，语义重复：

```
中场 | 中场     中场 | 前腰     前锋 | 右边     后卫 | 中后
```

第一格是角色组、第二格是具体位置，但显示成两个并排 chip，
「中场 中场」这种完全重复的占了一半。建议合并成一格（如「中场 · 前腰」）。

### B4. 桌面财政分类表：5/12 列内要求 608 px

`.finance-breakdown-card { grid-column: span 5 }`（1440 下约 515 px），
而 `#finance-breakdown-table { min-width: 38rem }`（608 px）→ **桌面档也要横滚**。

### B5. 全站有三套不同的球场画法 ⭐

| 位置 | 实现 | 有的线 | 宽高比（实测） |
|---|---|---|---|
| 开始页 `.start-bg-pitch` | HTML 元素（`index.html:44-50`） | 边线、中圈、中线、**两个禁区**、中点、**点球点** | — |
| 战术页 `.pitch` | **CSS 渐变**（`css/style.css:926`） | 只有中线 + 中圈 + 边框；**子元素里一个线的 div 都没有** | **430×538 = 0.800** |
| 比赛页 `.mp-field` | canvas / SVG | 完整 | **68/93.45 = 0.728** |

实测（`_ui-survey.mjs` 的 `tacticsPitch`）：

```
desktop  {w:430, h:538, ratio:0.800, computedAspect:"4 / 5", markings:[]}
phone    {w:334, h:417, ratio:0.800, computedAspect:"4 / 5", markings:[]}
```

`markings: []` —— 战术页球场里**没有任何** `.pitch-stripe` / `.pitch-center` /
`.pitch-box` / `.pitch-spot` 子元素（中线与中圈是 `.pitch` 自身的 `background` 渐变画的）。

两处问题：

1. **战术页球场没有禁区**。`.pitch-box` / `.pitch-box-l` / `.pitch-box-r` / `.pitch-spot`
   这套「禁区 + 点球点」样式**已经写好了**（`css/style.css:441-460`），
   开始页正在用（`index.html:47-49`），**战术页没有复用**——只是没插这几个 div。
2. **两个竖场形状不一样**：战术页 **0.800** vs 比赛页 **0.728**。
   同一批 11 个球员在「战术」和「比赛」两个页面出现在形状不同的球场上。
   （真实竖场 68m×105m = 0.648，两者都不是真值，但至少应当彼此一致。）

修法成本很低：战术页插 4 个已有 class 的 div，并把 `aspect-ratio` 对齐到 0.728。

### B6. 仪表盘：一张空卡 + 一组重复功能

- 「最近推进变化」卡在开赛前是**空占位**（"推进日期后，这里会汇总关键变化及其影响。"），
  与右侧 8 列宽的卡并排，形成一块死空间。
- 「首周引导」的 4 条检查项与「快捷处理」的 4 个按钮**功能重叠**
  （检查阵容 / 确认比赛计划 / 安排本周训练 / 完成第一场比赛）。

### B7. 赛前简报 form-strip 的「对」分隔符

`桑米尔 [W][W][D][L][W] 对 安克利 [L][D][L][W][L]`：
桌面一行放得下，手机档第二个 strip 被挤到下一行，两端不对齐。
建议改成两列 grid（队名 + 5 方块各占一行，中间不插「对」），任何宽度都对齐。

## C. 观感细节

- **卡片内嵌卡片**：工作台 card 里的「快捷处理」有自己的一层边框与底色，
  视觉上多一层框。建议内层改用无边框分区 + 分隔线。
- **暗色阴影偏重**：`--shadow: 0 8px 28px rgba(0,0,0,0.35)` 用在所有卡片上，
  暗底上几乎看不出层次、只显脏。建议暗色档降到 0.22 左右。
- **字号极小的辅助说明**：如球队页「本赛季联赛数据：出场/进球（门将为零封）/助攻
  （门将为失球）/场均/最近；状态为近 5 场滚动评分（含杯赛与洲际）」，
  信息密度高但字号小，建议拆成两行或改成可展开的说明。

## D. 建议的推进顺序

| 优先级 | 项目 | 理由 |
|---|---|---|
| **P0** | A1 字号令牌（6 级） | 影响 ~450 处声明，一页内 11 种字号是最刺眼的「不专业感」 |
| **P0** | A2 颜色令牌收口 | 164 个 hex / 两套并行调色板 |
| **P1** | A3 圆角+间距令牌 | 16 种圆角、`--radius` 只用 4 次 |
| **P1** | B1 桌面球场细条 | 观感最差，但需先定「谁让位」 |
| **P2** | B3 位置双标签合并 | 手机档高频页面 |
| **P2** | B2 手机顶栏压缩 | 释放 24% 屏高 |
| **P2** | B5 战术页球场补线 | 一致性 |
| **P3** | B4 / B6 / B7 / C | 局部优化 |

⚠ **A1/A2/A3 是同一件事的三面**（令牌收口），建议**一次做完**，
否则分三次改同一批声明容易互相冲突。且改动面极大（~1000 处声明），
**必须逐屏截图比对**，`browser-e2e` 只能验行为、验不了观感。

## E. 复现

```bash
# 12 个桌面页 + 5 个手机页的截图与逐页普查
node scripts/_ui-survey.mjs .tmp-continuity/ui-survey
# 输出：desktop-*.png / phone-*.png / ui-survey.json
#   每页 fonts 直方图 / card 高度 / 溢出 / chrome（顶栏占高）/ tacticsPitch（球场形状与线）

# 比赛屏 50 个 <11px 元素的清单
node scripts/_briefing-layout-probe.mjs .tmp-continuity/briefing-layout dark
```

⚠ 探针两个口径坑（已在脚本里修好，但换页面时容易再踩）：

1. **二级标签属于主导航分组**（`js/main.js:1628` 的 `MAIN_NAV_GROUPS`），
   非当前分组时按钮是 `hidden` 的，点击被 `.catch` 吞掉 → 截图不变。
   必须先点 `.primary-tab[data-nav-group=…]`。
   **判据：截图文件字节数相同 = 没切换。**
2. **表格内部元素在 `.table-wrap{overflow-x:auto}` 里会报「横向溢出」**，
   因为 `getBoundingClientRect()` 返回的是滚动内容的完整宽度。
   财政页 7 个、手机阵容 308 个、手机转会 609 个都属此类，**不是缺陷**。

原始数据：`.tmp-continuity/ui-survey3/`（截图 + `ui-survey.json`）、
`.tmp-continuity/briefing-fixed-dark/`、`.tmp-continuity/briefing-fixed-light/`。
