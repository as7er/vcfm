### 3.2 修掉一个让全量挂掉的缺陷（`42c756f`）—— **环境类，不是产品类**

第一次跑全量时挂在 `scripts/throwin-visibility-audit.mjs` 的变异测试上，报：

> 变异「①高光窗整块撤掉」红了但不是断言失败（**疑似环境错误**）

**这句话把环境问题说成了断言判别力问题，方向完全反了。** 两层根因，都已最小复现：

**① `spawnSync` 只给 `encoding` 会 EBUSY。** Node 这时用**默认 stdio**
（三路都是 pipe，**含 stdin**）⇒ 本环境下直接返回 `status: null` +
`error.code = "EBUSY"`，**子进程根本没启动**：

| 写法 | 结果 |
|---|---|
| `{encoding:"utf8"}` | ❌ EBUSY |
| `{stdio:["ignore","pipe","pipe"], encoding:"utf8"}` | ✅ |
| `{stdio:"inherit"}` | ✅ |
| 异步 `spawn(...)` | ✅ 不受影响 |

`verify.mjs` 和 `attacking-candidate-audit` 用的是 `inherit` ⇒ **它们不受影响**，
这正好解释了「为什么只有这一个审计挂」。

**② 守卫漏判 `null`。** `assert.notEqual(child.status, 0)` —— **`null !== 0` 也成立**，
于是启动失败被放行，最后被报成「疑似环境错误」。

**修法**：两处 `spawnSync` 显式写 `stdio: ["ignore","pipe","pipe"]`；
变异守卫改为**先断言 `child.error === undefined`（并打印 `error.code`）**再判退出码。
另一处同样踩坑的是 `scripts/_support-offer-equivalence.mjs`（`_` 前缀诊断脚本）。

**验证**：该审计 **exit 0**，**5/5 变异测试都正确变红（AssertionError）**。

> **通则：看到「红了但不是断言失败」这类提示，先怀疑子进程有没有真的跑起来。**
