# 门将出球的短传/长传比例与出球方向 —— 诊断与候选评估（2026-09-14）

## 0. 一句话结论

**回答用户的问题**：门将**短传/长传的比例本身是分语境的**，按语境拆开后差异 10 倍且各自自洽；
**纵向出球方向正常**；**横向出球方向不合理**（91% 砸中路），但那是既有评分权重的有意结果，
不是缺陷。

**顺带查出一处真缺陷**：`recvOk`（「接球人不能太靠后、也不能太近」）是**对第 1 名候选做事后
否决**，否决之后**不退而求其次**。改动前，**43.7% 的大脚**本来存在「合格且过门槛」的更好选择。

**但该修复未被采纳**：它在 `verify --full` 实际使用的 24 场门槛上，两档都跌破进球护栏
（标准 1.79、后台 2.46，下限 2.5），因此**已回退**。探针、候选与全部原始统计保留在本文件中。

## 1. 触发

用户提问（2026-09-14）：

> 「继续主线之前，我想了解一下守门员在开球的时候，采用短传还是长传，
> 以及出球方向的设定是否正常合理。」

这是对**主线（全局跑位）之外**插入的一项独立调查。按项目规矩，先做纯测量，
拿到证据再决定改不改。

## 2. 测量工具

新增 `scripts/_gk-distribution-shape-probe.mjs`（**只读**：只包装 `_gkDistribute` /
`_passCandidates` / `_pass`，打标记，**不消费随机数**，因此不改变比赛轨迹）。

用法：

```bash
node scripts/_gk-distribution-shape-probe.mjs [场数] [种子基]
# 本轮口径：8 场，种子 880000..880007，standard 档，能力 15，4-3-3
```

它与既有 `scripts/_gk-kick-and-ball-jump-probe.mjs` 的分工：那个解决「球瞬移」与
「大脚出界」，顺带记短/长计数；本探针只做出球**决策本身**的拆解，补上三件它没测的事：

1. **按重启语境分开统计**。门球（`restartType === "goalkick"`）时对手本该在禁区外，
   门将的选择与「扑救后抱球」完全不同；混在一起算会把两种场景的平均值当成一种行为。
2. **横向通道**。旧缺陷是「100% 落在中场中路」，现在是否还挤在中央？
3. **短传分支逐道门的失败原因**。`recvOk` 有两个子条件（不许太深 / 不许太近），
   原实现只报「不合格」不报是哪一条。

⚠ 探针挂钩的是 `_passCandidates` 而**不是** `_bestPass`：门将分支在候选实现下不再走
`_bestPass`（它只返回第 1 名）。挂钩 `_bestPass` 会报「未被调用 100%」，那是挂钩失效，
不是引擎行为。

## 3. 诊断（基线 = `868479d`）

### 3.1 短传 / 大脚：总体 24.6%，但按语境拆开差 10 倍

| 语境 | 次数 | 短传 |
|---|---|---|
| **全部** | 516 | **127（24.6%）** |
| 门球 `goalkick` | 109 | **91（83.5%）** |
| 非门球（抱球 / 回传） | 407 | **36（8.8%）** |

两种场景各自都自洽：门球时对手在禁区外、门前无人，真实门将本来就该短传发动；
扑救后抱球时对手已回到位置，长传找前场是正常选择。**所以「总体 24.6%」这个数字本身
不能作为缺陷证据**——它是一个混合比例。

顺带确认一处**已经修好**的旧缺陷没有复发：门球被误判为贴身压迫 **0/109**。
旧阈值 6.5 格把站在禁区线外的合法逼抢前锋（固定站 `(50, 83.5)`，离门将 6.0~6.3 格）
当成「扑到门将脚下」，实测 113 次出球里 112 次判为贴身、短传分支从未触发；
现在阈值收到 4 格，门球样本的最近对手距离中位 6.1 格，**0 次误判**。

### 3.2 出球方向：纵向正常，横向不合理

**纵向正常**：

- 朝进攻方向推进中位 **+10.0 格 ≈ 10.5 m**
- 推进量 ≤ 0（仍在本方半场）仅 **19/389（4.9%）**
- 推进量 < 5 格（几乎没往前）**45/389（11.6%）**

旧的 `dir * -X` 符号 bug 已修，现在的纵向分布落在真实的「中线前后」一带。

**横向不合理**：

- 通道分布 **左 19 / 中 354 / 右 16 → 中路 91.0%**
- 落在「中路盒」（`x∈[30,70]` 且推进 `∈[−12,12]` 格）**276/389（71.0%）**
- 只有 **159/389（40.9%）** 瞄了具体接应人

后果是真实的：同 8 场统计大脚落地后**第一个控住球的人**——
对手 **311** / 本方 **83**（有人控住的 394 次里对手占 **78.9%**）。

**但这不是缺陷，是有意的**：落点横向被 `clamp(m.x + inward * 6, 30, 70)` 夹在
`x∈[30,70]`，评分里 `central * 22` 权重很高，代码注释写明目的是「远离边线给落地滚动
留余量」，避免旧实现「门将开大脚直接滚出边线」。二点球丢得多是**长传本身的性质**
（真实比赛长传的二点球也是对手略占优），不是可以靠调权重修掉的 bug。

### 3.3 核心缺陷：`recvOk` 事后否决且不退而求其次

逐道门拆解那 389 次大脚：

| 关卡 | 结果 |
|---|---|
| ① `_passCandidates` **根本没被调用** | **252/389（64.8%）** |
| ② 被调用但返回 null | **0/389** |
| ③ 有候选 | 137 次 |
| ④ 第 1 名候选 `recvOk` 不合格 | **137/137**，其中**接球人太深 93.4%**、太近仅 3.6% |

第 ① 道是 `underHeavyPressure`（最近对手 < 4 格或 9 格内 ≥2 人）与
`launchesCounters` 反击习惯（62% 概率）的**有意短路**——受压门将不开短传是对的。

第 ④ 道就是缺陷。决定性证据：

- 第 1 名候选的**角色**是 `{DEF: 79, ATT: 50, MID: 8}`，`y` 中位 36.5；
  按队拆开：home 第 1 名 `y` 中位 **88.1**（范围 71.2~92.5），违反 `y < 82` 的 **64/68（94.1%）**，
  距门将中位 **11.7 格**；away 对称（`y` 中位 10.7，违反 **64/69**，距门将 12.2 格）。
  → 引擎挑中的是**站在六码区边缘的中卫**。
- 用与 `recvOk` **完全相同**的两条判据对**所有**外场球员各复算一遍：
  **389/389（100%）** 都至少有 1 个合格对象，合格对象数中位 **6**（共 10 名外场），
  最大 10。**一个都没有的占比 0.0%**。

也就是说：**短传分支不是因为「无人可传」才走不通，是因为选中者不合格时没有退而求其次。**

成因在代码形状上很直接：`_bestPass(a)` = `_passCandidates(a)[0]`，只取第 1 名；
而 `_passCandidates` 按 `value = (0.35 + advance) * safety * distPen * coreBoost` 降序排列，
门将持球时几何最近的中卫 `advance` 很小、`distPen` 却最优，于是排第 1；
它的 value 过得了 `0.22` 门槛，却过不了 `recv.y < 82`。

### 3.4 顺带确认：`_bestPass` 的其它使用者不受影响

`_bestPass` 仍被界外球 / 任意球等重启路径使用（`engine.js:2341`、`:2384`、`:2454`），
**没有变成死代码**，其语义（返回第 1 名）也未改动。

## 4. 候选改动（最小，**已回退**）

只改 `js/sim/engine.js` 的门将分支（`_gkDistribute`），把 `recvOk` 的两条判据
**并入候选筛选**，而不是对第 1 名做事后否决：

```js
const shortThreshold =
  (prefersShort ? 0.15 : 0.22) - this._roleBehavior(a, "shortDistribution") * 0.04;
let passTo = null;
if (!underHeavyPressure && !bypassBuildUp) {
  for (const option of this._passCandidates(a)) {
    if (!(option.value > shortThreshold)) break; // 已按 value 降序，后面只会更小
    const recv = option.agent;
    if (!recv) continue;
    if (a.team === "home" ? !(recv.y < 82) : !(recv.y > 18)) continue;
    if (!(dist(recv.x, recv.y, a.x, a.y) > 8)) continue;
    passTo = option;
    break;
  }
}
if (passTo) {
  this._pass(a, passTo);
  return;
}
```

**没有改动**：打分权重（`value` 公式一字未动）、跑速、射门精度、扑救概率、
门槛数值（`0.15 / 0.22 / 0.04`）、`underHeavyPressure` 与 `bypassBuildUp` 的判定、
大脚落点区间。因此这不引入任何为预设结果服务的隐藏加权。

## 5. 决策层的直接效果（同 8 场、同种子 880000..880007）

| 指标 | 改动前（`868479d`） | 改动后 |
|---|---|---|
| 短传 | 127/516（**24.6%**） | 173/536（**32.3%**） |
| 大脚 | 389/516（75.4%） | 363/536（67.7%） |
| 门球短传 | 91/109（83.5%） | 90/111（81.1%） |
| **非门球短传** | 36/407（**8.8%**） | 83/425（**19.5%**） |
| 大脚中「仍有合格且过门槛的更好选择」 | 59/135（**43.7%**） | 0/67（**0.0%**） |

关键读法：

- **门球基本不变**（83.5% → 81.1%）——本来就正常，修复不该动它，确实没动。
- **非门球翻了一倍多**（8.8% → 19.5%）——这正是被 `recvOk` 事后否决吃掉的那部分。
- **剩余大脚已无可优化空间**：363 次里 295 次（81.3%）连 `_passCandidates` 都没调用
  （受压 / 反击习惯，有意短路）；调用了的 68 次中，**合格候选的最高 value 过本条真实门槛的
  0/67（0.0%）**。也就是说每一脚大脚都不存在「合格且过门槛」的更好选择。

> 门槛口径说明：探针按**每条样本自己的真实门槛**
> `(prefersShort ? 0.15 : 0.22) − _roleBehavior(a,"shortDistribution") × 0.04` 判定，
> 而不是硬写 0.15。本组真实门槛中位 **0.143**，最低可到约 0.11；
> 固定阈值口径（`>0.15` / `>0.22`）作为参考一并打印，两者结论一致。

**方向基本未变**：中路 337/363（92.8%）、推进中位 +10.3 格、瞄接应人 41.3%。
符合预期——本次改动没有碰横向选择。

**未走短传的 363 次里合格对象数中位 5**：这在修复后是**正常**的（门将已在整张表上逐个筛，
筛完仍开大脚，说明过门槛的都不合格）。第 2c 节「有 ≥1 个合格对象却仍然开大脚 = 100%」
在两代引擎里都会是 100%，**不能**再当作缺陷证据——探针注释里已写明这条读法分两个时代。

## 6. 轨迹级验收：**失败**，候选不采纳

结果如下（全部为同机、同 Node、同口径；基线用 HEAD 版引擎的独立副本复现）。

两档**失败点都在进球护栏**。注意**射门数与射正数几乎不变**，掉的是**转化率**。

### 6.3 配对同种子检验（`scripts/_goals-paired-seed-probe.mjs`）

只比均值无法区分「系统性下降」与「混沌重掷」。用**同一批 48 个种子**跑两台引擎、
逐场比对：

| 档 | 基线 | 候选 | 配对差 | t | 降/平/升 |
|---|---|---|---|---|---|
| standard | 2.875 | 2.250 | **−0.625**（SE 0.312） | **−2.00** | 28 / 6 / 14 |
| background | 3.271 | 2.438 | **−0.833**（SE 0.351） | **−2.37** | 25 / 7 / 16 |

两档都偏负，符号比约 2:1。作为噪声尺度参照：**同一台引擎**把 48 场劈成两个 24 场半区，
半区均值之差为 **standard 0.25 / background 0.79** —— 也就是说这个引擎的种子间波动
本身就有 0.25~0.79 球/场。**配对检验因此比裸均值可信，但仍不足以把效应量钉死**；
可确定的是方向为负、量级约 −0.4 ~ −0.85。

### 6.4 `verify --full` 实际使用的那两条 24 场命令（**两档均退出 1**）

`verify.mjs:121-122` 跑的是 `match-realism-audit.mjs 24`（不是 48），因此单独验证：

| 命令 | 结果 | 失败断言 |
|---|---|---|
| `match-realism-audit.mjs 24` | **退出 1** | `goals per match left the calibration envelope` |
| `match-realism-audit.mjs 24 background` | **退出 1** | 同上 |

24 场门槛也红，所以 **`verify --full` 会在第 94/95 个入口（`verify.mjs:121-122`）失败**，
无需再花约 1 小时跑完整套件。
（`verify --full` 未被完整执行，这是**有意跳过**，理由记录于此。）

### 6.5 机制**未能**被隔离：进球不是「大脚占比」的函数

为了判断「少开大脚」是不是直接原因，另做两个强制变体，同 24 种子、后台档：

| 变体 | 大脚占比 | 进球/场 | 射门/场 | 射正/场 |
|---|---|---|---|---|
| 强制 100% 大脚 | 100% | **3.000** | 26.38 | 9.71 |
| 基线 `868479d` | 75.4% | **2.875** | 26.21 | 9.25 |
| 候选（本次修复） | 67.7% | **2.458** | 26.13 | 8.92 |
| 只要有合格对象就短传 | 最低 | **2.667** | 26.38 | 9.83 |

**曲线非单调**：把门将改成 100% 大脚（对出球行为的扰动远大于本次修复）只让进球从
2.875 动到 3.000（+0.125），而本次修复只改了约 5 次/场的出球却掉了 0.417。
两个量级对不上。

因此**不能**写成「大脚是进球的来源，所以少开大脚就掉球」。更诚实的结论是：

> 这个引擎的进球产出对**极小的扰动**高度敏感，且该敏感度**不能用门将出球变量本身解释**。
> 也就是说，护栏当前的通过/失败边界，有很大一部分是**混沌重掷**而不是模型性质。

这一点本身是有价值的发现，应带到主线（全局跑位）里：任何轨迹级改动都可能让
2.88 变成 2.25 或 3.30，**单次 24 场通过/失败都不能当作因果证据**。

### 6.6 结论

| 项目 | 结果 |
|---|---|
| 缺陷是否真实 | **是**（43.7% 的大脚有被忽略的更好选择，证据在 §3.3 / §5） |
| 改动是否最小、是否引入隐藏加权 | 是（未动任何权重与参数） |
| 是否通过护栏 | **否**（24 场门槛两档皆红，进球跌破 2.5） |
| 处置 | **回退**，候选与全部原始统计归档于本文件 |

**不做的事**：不为了让红变绿而放宽 `2.5~3.3` 真实性上下界，也不刷新冻结参考——
按项目规矩，真实性上下界与所有容差保持原值（参照 `match-realism-audit.mjs` 内
历次「有意刷新」的注释：只有**真实性与门槛保持原值**时才允许刷新参考）。

## 7. 仍未解决 / 保留项

- **横向 91% 集中中路未改**。它是既有评分权重的有意结果（防贴边滚出界），
  且「二点球对手占 78.9%」是长传本身的性质。若要改，属于**独立的**设计变更。
- **门球短传 81.1% 偏高**（真实门将视战术约 50~70%）。这是
  `prefersShort` / 门槛 / 门球时对手站位的联合结果，本次未动。
- **`recvOk` 的事后否决缺陷仍然存在**。它是真缺陷，但单独修会跌破护栏；
  合理的做法是**与「深位组织的射门质量」一起改**（修好从后场发起的进攻质量，
  再放开门将的短传选择），那属于主线范围，不在本轮。
- **进球对微小扰动的高度敏感性**（§6.5）是本次最有价值的副产物，
  应作为主线的前置认知。
- 门将专项审计中 `goalkeeper-relative-contact-audit` / `ball-release-goalkeeper-audit` /
  `goalkeeper-contact-height-audit` / `goalkeeper-reaction-clock-audit` 四项退出 1，
  **均不在 `verify.mjs` 套件内**，且在改动前的引擎副本上同样退出 1 ——
  是既有的「记录已知缺陷」审计，**与本次改动无关**，也不属于本次回归。
