**根因（AGENTS.md `:3303-3307`）**：`_thinkAttackOffBall` 是**逐 tick 位置控制器** ——
目标每 **0.42~0.82 秒**按当前球位重算一次，球员**永远只需走几米就到位**。
所以任何公式改动都只是**换个地方站住**。**它没有「跑动」这个原语**
（有时长、有触发条件、有到达时刻）。

## 4. 现有机制的确切缺口

### 4.1 `resolveOffBallTarget` 的 1.5s 租约是**防抖**，不是跑动

`js/off-ball-movement.js:113-130`：

```js
const leaseActive = sameContext && finite(now) < finite(previous?.until, -Infinity);
const holdPrevious = !urgent && leaseActive && targetChanged && reversal &&
  oldTargetRemaining >= config.oldTargetRemainingMetres;
```

三个合取条件：**目标变化 ≥5.5m** + **方向反转 ≥129.6°** + **旧目标还差 ≥2.4m**。
满足时才「锁住旧目标」。它的作用是**防止球员被来回撕扯**，
**不产生任何位移**，也**没有「跑到」的语义**。

### 4.2 两条「锚在球上」的公式造出 −10.6m

**`_chooseAttackOffBallTarget:3826`**（`mid-2nd-layer` 分支）：

```js
a.ty = clamp(b.y - dir * (15 + rank * 3.5), 12, 88);
```

**`_applyPassSupport:3601`**（二次覆写，同一批球员）：

```js
const depth = Math.max(17 + rank * 6, Math.abs(this.ball.y - goalY) + 6 + rank * 5);
a.ty = clamp(goalY - this.attackDir(a.team) * depth, 3, 97);
```

两条都**把目标钉在「球/球门 + 常量偏移」**上。球不动，目标不动。

### 4.3 v252 新增的第三人跑位是**触发型**，但只覆盖传球后

`_applyPassSupport:3585-3595` 的 `_passSupportRun` 需要
`plan.until` + `attackSince` 校验 —— **只在一次传球被触发后生效、到点结束**。
方向是对的（正是「触发型可行、常驻型会撞 gate」那条规矩），
但它**只覆盖传球之后**，不改变**无球默认状态**下的纵深分布。

## 5. 设计：给目标附加「到达时刻」

**核心改动**：把「目标点」升级成「**带到达时刻的跑动**」。
不是改坐标，而是**给目标加一个必须跑到的时点**。

```
跑动 = { x, y, setAt, arriveBy, committed }
```

- **`arriveBy`（到达时刻）**：由球员当前位置与目标距离、按其可用速度算出
  （`距离 / 可用速度 + 余量`）。在 `arriveBy` 之前，**目标不被重算**——
  即使球的移动让「最优目标」变了，也**先跑完**。
- **`committed`（已承诺）**：跑动期间如果球的位置变化使该目标**明显失效**
  （例如球已越到目标身后、或队友已占位），仍允许**显式取消**
  （`urgent` 路径），但取消要有**代价判据**，不是每 tick 免费重算。
- **触发条件**（不是常驻）：只在**满足真实足球的跑动动机**时进入承诺态，例如
  - 球在可传球距离内且该球员是**该纵深的唯一候选**；
  - 球队刚赢回球权（转换窗口）；
  - 传中/倒三角窗口打开。
  ⇒ **避免**「所有人都一直跑」那种常驻型改动（会撞 `crowdedPairs` 与越位 gate）。

**为什么这与前六次不同**：前六次改的是**坐标公式**，跑动的**时长恒为「走到为止」**；
这次改的是**承诺语义**——目标是**必须跑到**的，球员在 `arriveBy` 之前**不接受**新目标。
位移因此**真的产生**，而不是换个地方站着。

**与越位的配平**：`arriveBy` 只在**目标不越位**时给（越位线以内）；
越过防线的纵深仍由 `_clampOffside` 管。这样：
- 位移来自「**跑到**线前的合理纵深」，不是「**站在**线后」；
- 越位不会像 `release{R}` 那样被打到 24~37 倍。
（`release{R}` 的教训：允许把防线**身后**当目标 ⇒ 永久站在越位位置。这次**不允许**。）

**四项都朝 v252 的目标方向走**（循环↓、直塞↑、越位↓），**但进球掉了 0.67**。

- `match-realism-audit`（能力 13、含强弱对阵、24 场）**没有捕捉到这次下降**：
  今天跑出来仍是 2.79~2.88 ✅。两者口径不同（能力 15 同强度 vs 能力 13 + 强弱），
  **不是矛盾，而是暴露了「进球护栏只在一种口径上」**。
- 这正是本项目反复出现的**口径盲区**：一个指标在 A 口径绿、在 B 口径红。
  ⇒ **不能只看 `match-realism-audit` 判进球健康度**。

**⇒ 结论：主线的第一优先项不是「跑动原语」，而是先查清 2.92 → 2.25 这 0.67 球丢在哪。**
否则跑动原语的标定曲线没有可用的进球基线（现状已在带外，加任何档位都无法解释读数）。

候选方向（按可疑度排，均需实测）：

1. **传中占比 4.21% → 3.36%**（护栏下限 3%，余量只剩 0.36pp）。
   v252 的「传中可达性」改动要求「连接球人的乐观运动上界加现有触达距离都够不到就不能承诺」，
   这会**减少传中**——而传中是进球的重要来源之一。
   ⚠️ **但这条在另一个口径下不成立**：`match-realism-audit` 今天读 `crossSharePct` = **5.0%**，
   在护栏 3~14% 中部。所以「传中下降」只在探针口径下显著，**需要先查清两个口径的传中定义差异**
   （探针按「合并双方传中 ÷ 传球」，audit 的口径见其 `:406`）。
2. **禁区触球 276 → 139（−49%）**。v252 的「近门资格修正」让射门更挑剔；
   禁区触球腰斩可能是射门机会减少的直接来源。
3. **越位 4.54 → 1.75（−61%）**。留档 `:4047` 曾测出「每减少一次越位停顿约多 0.15 个进球」，
   但那条弹性在门将改动后**归零**；现在需要重测——**如果弹性又回来了，
   那就说明「越位曾给进攻当刹车」这个机制在 v252 之后重新成立**。
