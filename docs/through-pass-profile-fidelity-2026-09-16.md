## 2. 两档在直塞结果上的差异（同种子配对，24 场/档）

新探针 `scripts/_through-pass-profile-fidelity-probe.mjs`：同种子 372000..372023
分别在两档跑完整场，从事件流给每一脚直塞归类结局。**纯观测，不改引擎。**

| 直塞结局 | 标准档 | 后台档 |
|---|---:|---:|
| 直塞总数 | 45 | 54 |
| 成功接到（预定接球人） | **48.9%** | **55.6%** |
| **丢失**（出界／松球被对手捡到） | **44.4%** | **20.4%** |
| 被断 | 2.2%（1 次） | 13.0%（7 次） |
| 被踢掉（tackle） | 2.2% | 1.9% |

⚠ **口径说明（必须知道才能读这张表）**：`_beginBallControl` 只在
`emitReceive: wasPass && best.team === b.kickTeam` 时发 `receive` 事件
（`js/sim/engine.js:6208`）——**对手控到球时不发事件**。所以探针里「下一个传球来自对手」
这一桶的真实含义是「**这脚直塞丢了**」（出界重启，或松球被对手捡走后出球），
不是「被对手接到」。探针的 `received-by-opponent` 计数因此恒为 0。

**读法**：后台档**两头都更多**——接到更多（+6.7pp）、被断也更多（+10.8pp），
而「丢在无人区」少了一半以上（−24pp）。
这个形状**不能直接读成「粗步长让防守者漏判」**：如果只是防守漏判，
应该是「接到更多、被断更少」。实测是**被断也更多**。

## 3. 两档的结构差异

`js/sim/adapt.js` 的 `SIMULATION_PROFILES`：

| 参数 | 标准档 | 后台档 |
|---|---|---|
| `timeStep` | 0.1 | **0.3** |
| `separationPasses` | 8 | **4** |

以及 `_stepOnce` 的积分结构（`js/sim/engine.js:1732-1768`）：

- **球物理**按 `ceil(dt / 0.1)` 细分（0.3 → 3 子步），但**只在
  `_ballPhysicsFineReason(dt)` 非空时**——条件是「有球员在球未来 `dt` 秒的预测路径
  `CONTROL_RADIUS_METRES + 2 = 4.6m` 内」，**射门则永远细分**。
- **球员移动**：只有门将在 `_goalkeeperNeedsFineMovement` 时细分，其余球员**按 `physicsDt` 走**。
- `_separateAgents(separationPasses, ...)`：8 趟 vs 4 趟。

⚠ **`_separateAgents` 里那条后台档专属的提前退出是安全的**，不是缺陷：
`if (simulationProfile === "background" && (|dx| >= 3.35 || |dy| >= 3.35)) continue;`
而 `minD = SEPARATION_MIN_DISTANCE_UNITS = 2.85`。`|dx| >= 3.35` ⇒ 距离 ≥ 3.35 > 2.85，
不可能重叠。**这条跳过是保守且精确的**（先算再断言，别看到 profile 分支就当成 bug）。

## 4. 机制候选：拦截判定是**点采样**

`_resolvePossession` 里的飞行拦截（`js/sim/engine.js:5909`）：

```js
const d = pitchDistanceBetween(o.x, o.y, b.x, b.y);   // 只看"当前这一瞬"的球位
if (d < SIM.CONTROL_RADIUS_METRES + 2.4) { ...按概率抢截... }
```

这是一次**点采样**：防守者必须落在**某次调用时**的球位 5.0m 内。
球 15 m/s 时：

- 标准档每 0.1s 采一次 → 采样间距 1.5 m → 只有垂直距离 p ∈ (4.94, 5.0) 的窄环带可能被跳过；
- 后台档（未细分时）每 0.3s 采一次 → 间距 4.5 m → 危险环带 p ∈ (4.47, 5.0)，**约宽 10 倍**。

所以**同一物理情形，两档会给出不同结果**——这本身就是保真度缺陷。

⚠ 但**这条机制预测的方向是「后台档被断更少」**，而 §2 实测是**被断更多**。
所以要么机制不是主因，要么它与另一个方向相反的主因叠在一起。

### 4.1 实验一：强制全程细分（**已被混淆，不能作结论**）

`scripts/_always-fine-step-candidate.mjs` 让后台档每一步都细分球物理。结果：

| 指标 | 标准档 | 后台档原样 | 后台档强制细分 |
|---|---:|---:|---:|
| 直塞完成率 | 48.9% | 55.6% | **45.8%** |
| 被断 | 1 | 7 | 5 |
| 进球/场 | 2.08 | 2.75 | **3.58** |

完成率差**确实消失**（55.6% → 45.8%）。但**这个实验不干净**：
强制细分同时把 `_resolvePossession`／`_contactFineReason`／`_separateAgents` 等
**每次调用**的判定的调用次数变成 3 倍，不只是采样变密。
证据就是进球从 2.75 冲到 **3.58（远超护栏上限 3.3）**——它不是「更保真」，
而是改变了别的东西。**所以不能用它判定机制。**

### 4.2 实验二：线段拦截（**已写、未跑完**）

`scripts/_segment-intercept-candidate.mjs` 把点距离改成**到本步扫过线段的距离**
（复用 `b._prevX/_prevY`，与 `js/sim/engine.js:5690` 门将反应代码同一套重建）。
它**只改几何、不改调用节奏**，是单变量实验。

## 5. 统计口径（不能忽略）

- 直塞样本只有 **45 / 54 脚**。完成率 48.9% vs 55.6% 的差（6.7pp）
  对应的**标准误约 10pp** —— **落在噪声内，本轮不足以主张它是真差异**。
- 进球 2.08 vs 2.75 的差（+0.67/场）在 24 场里约 2 个标准误，**边缘**；
  而 `match-realism-audit` 的 24 场（另 24 个种子）两档只差 0.17。
- **要判定机制，样本量不够**：按 6.7pp 的差、想拿到 80% 功效，需要约
  **300+ 脚直塞**（≈ 140 场/档）。这是本轮最重要的限制。
