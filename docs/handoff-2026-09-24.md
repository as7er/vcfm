## 4. FM26 球员智能对比（取证，不改代码）

**结论：不是「高度一致」，更谈不上超越。** 局部机制扎实，决策输入的广度与权重差距大。

**已核实的事实**：
- 球员属性 **19 项**，精神属性只有 `decisions` / `vision` / `positioning` 三项；
  FM 系列约 36 项可见属性，其中精神属性约 14 项（另有隐藏属性）。
- 战术旋钮 5 个（style/pressing/tempo/width/defensiveLine）+ 角色/职责/习惯，
  且 `scripts/tactics-response-verify.mjs` 常驻断言它们真的改变行为。
- 无球跑动有 third-man-run / cutback-outlet / one-two / 接应分层。
- ⚠ FM26 那一列是**系列通用特征**，不是针对 FM26 实测（网络搜索返回 429，无法核 FM26 新引擎细节）。

## 9. 会话教训（值得沿用到下一轮）

1. **「已撤销」的改动要逐行核对**：上个会话注释写着撤销，实际把一行**无关的防护代码**一起删了。
   注释与代码冲突时，以代码 + `git diff` 为准。
2. **口径先于结论**：形状分析第一版把角球/球门球算进「后三区防守」，读出「中位 1 人」，
   排除底线 12 格后才可信。直播模式**偏爱定位球片段**，任何「整场占比」都要先问采样是否均匀。
3. **留在前场不等于不回防**：必须按位置拆（本轮 ATT 204 / DEF 0）。
4. **属性 A/B 要用产品路径造队**：手搓球队缺一项属性会被默认成能力 10，读数不可比
   （本轮探针走 `createWorld` → `createMatchSession` → `ensureSimEngine`）。
5. **后台档红先查基线**：本轮后台档退出 1，用 `git archive HEAD` 的副本复跑才确认是既有的。
6. **别用 PowerShell 往返改源文件**（会写坏 UTF-8 中文，见上一份交接 §9.5）；
   本轮 `sed` 替换中文时也出现过一次乱码，改完必须搜一遍 `\uFFFD`。
