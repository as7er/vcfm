比分条的 62px 花在哪（读 CSS，未另测）
--------------------------------------
`.fmm-sb-top` 是三列 grid，高度 = 三列最高者：

- 左右列：`fm-sb-kit`（队徽 30px）
- **中列 `.fm-sb-center` 竖排三行**：`fm-sb-comp`（赛事名 11px）
  + `fm-sb-clock`（时钟，横屏 1.05rem≈16.8px×1.1）
  + `fm-sb-live`（LIVE 徽章 10px），行间 `gap 0.15rem` + `margin-top 0.1rem`

⇒ **中列的三行竖排是高度主因**，不是队徽。横屏已有 `.fm-sb-short`
与 `.fmm-stats-toggle` 的隐藏规则，但**中列没有压扁**。

### 🔴 第一版指标错在哪（值得记）

第一版把「可见球场」写成 `球场盒 − 比分条遮挡`。这个口径下
「控球率条改浮层」看起来 **+24px** —— 但那是**假的**：

> 控球条从「球场**下方**」搬到「球场**底部压住**」。球场盒确实从 206 长到 230，
> 但底下那 22px 被控球条自己盖住了 —— **没多看见一个像素。**

修正后必须**同时减掉两个浮层**：
`可见 = 相机渲染高 − 比分条遮挡 − 控球条遮挡`。
修正后控球条浮层是 **+17.6**（球场盒变大带来的净收益），远小于 24。

⇒ 通则：**「盒子变大了」不等于「看得更多了」**。量「看得见多少」时，
每个可能盖住它的东西都要减一遍。这正是 `ui-layout-audit` 里
「量错量」那一类坑的又一例。

⚠ 为什么**不建议**「控制条整条自动隐藏」
----------------------------------------
用户提议「不用时隐藏」。**整条自动隐藏会重蹈 v276 的坑**：
v276 刚做完「全屏键可发现性」（控制条 6 个图标键同色同尺寸、用户找不到 ⇒
改成主题色高亮 + 开赛 toast 提示一次）。把整条藏起来，那个按钮又找不到了。

更稳的三条路（都保留可发现性）：
1. **点球场 = 沉浸模式**：比分条 + 控球率条 + 控制条一起淡出，再点回来。
   视频播放器的标准手势，用户不用学。**推荐**。
2. **只藏低频键**：保留 暂停 / 全屏 / 倍速，把「逐事件 / 音效 / 快照 / 摄像机」
   收进一个 `⋯` 展开。
3. **自动淡到 35% 不透明度**（不是消失）：播放中 N 秒无操作 ⇒ 变淡，仍可见可点。

⚠ 同轮发现的**既有红**（与本轮改动无关，别误算在我头上）
--------------------------------------------------------
`scripts/background-spatial-worker-audit.mjs` **失败**：

> prepared worker clock and ordered commit must equal the synchronous result

失败内容是 **体能精度不一致**：worker / 有序提交路径给出**整数**
（80 / 88 / 89 / 76），同步路径给出**小数**（77.82507430934491 / 94.76541816359754 …）。

已用 `git worktree` 逐提交验证（**不动工作区**）：

| 提交 | 结果 |
|---|---|
| `721d807`（v277，v278 **之前**） | ✅ 通过 |
| `aa6d100`（**v278** 终场体能改为按跑动距离分摊） | ❌ 失败 |
| `ba679b8`（v282，本轮基线） | ❌ 失败 |

⇒ **回归由 v278 引入**：它让同步路径的体能变成小数，但后台 worker 路径仍是整数，
两条路径从此不一致。这条审计正是为此设的护栏，**却一直没人跑**（交接写「不必先跑 verify」）。

**本轮没有修**（需要先定方向：是让 worker 路径也对齐小数，还是让同步路径回到取整 ——
后者会撤销 v278 的设计意图）。全量 `verify.mjs --full` 在这个脚本处中断，
它之后的审计本轮**没有执行到**。
