================================================================================
半场换边「门将换位太慢 / 被进空门」—— 归档
================================================================================
日期：2026-09-20
用户报告：**「下半场换边的时候，双方守门员换位好像比较慢，是不是会导致被进空门」**
改动：js/match.js 的 `applyHalfTimeSwap()` —— 换边重同步后补一次 `eng._kickoff("away")`
仪器：scripts/_halftime-gk-swap-probe.mjs（新建，含「现状 vs 修复后」对照）


================================================================================
[0] 一句话结论
================================================================================
**换边后没有重新开球**，而 `resyncSimAfterHalfTime` 只改阵型锚点、不吸附球员坐标，
于是两队门将在换边那一刻**站在距新球门约 100m 的对侧**，要跑 **7~17.6 秒**才回到门前。
这段窗口球门是空的 —— 用户的怀疑成立。

修复：换边重同步后补一次 `_kickoff("away")`。
实测对照（6 场同种子）：
  · 换边瞬间门将距新球门：**97.2m / 99.4m** → **4.0m / 6.1m**
  · 回到门前 ≤15m 用时：**均值 14.5s（最慢 17.3s）** → **0.1s**
  · 同种子逐位：**只改了下半场开头这一段**，上半场与其它机制未受影响。


================================================================================
[1] 根因链（读码 → 实测）
================================================================================
1. 下半场换边由**调用层**发起（合同 A：引擎不认比赛时长）：
   `js/match.js:1419` `if (fromMin === 46 || state._simNeedsResync) applyHalfTimeSwap(...)`。
2. `applyHalfTimeSwap`（`js/match.js:1402`）做两件事：
   `eng.endsSwapped = true` + `resyncSimAfterHalfTime(state)`。
3. `resyncSimAfterHalfTime`（`js/sim/adapt.js:83`）**只写 `a.baseX/a.baseY`（阵型锚点）**，
   **不碰 `a.x/a.y`**（球员实际坐标）。
4. 真正做吸附的是 `_kickoff`（`js/sim/engine.js:8176`）里的
   `a.x = a.baseX; a.y = attackingUp ? 50 + a.baseY * 0.48 : a.baseY * 0.48`。
   但 `grep -n _kickoff js/sim/engine.js` 只有两处调用：
   **`:662` 开场**、**`:2009` 进球庆祝结束后** —— **下半场没有任何一处**。
5. 门将的目标位由 `_thinkGK`（`:2305`）的
   `clampGkY(...)` 给出，而它围绕 `goalY = this.ownGoalY(a.team)`；
   `ownGoalY`（`:854`）带 `this.endsSwapped ? 100 - base : base` —— **瞬间翻转**。
⇒ 合成结果：换边那一刻门将的**目标**跳到对面球门，**身体**还在原地。

🔑 **通用形态**：**「目标位随开关翻转」与「身体位置随之搬迁」是两件事。**
   只翻目标，球员就得自己跑过去。凡是「某个状态开关会改变所有实体的目标位」，
   切换开关时都必须同时决定**身体怎么过去**（吸附 / 走过去 / 不允许切换）。

[3] 修法与为什么是这个修法
================================================================================
在 `applyHalfTimeSwap` 里，`resyncSimAfterHalfTime(state)` **之后**补：
    if (fromMin === 46) eng._kickoff("away");

为什么用 `_kickoff` 而不是自己写「吸附坐标」：
1. 它正是**开场/进球后**在用的同一套已测代码（吸附 + 清速度 + 清 FSM/朝向 + 摆开球人）；
   自己再写一份「吸附」等于把同一逻辑抄第二遍 —— 本项目已多次因重复入口吃亏
   （见引擎里 `ownGoalY` 重构的注释：`home ? HOME_GOAL_Y : AWAY_GOAL_Y` 被抄了 6 遍）。
2. 真实足球里**下半场就是从开球开始的**（不是接着上半场最后一脚继续踢），
   所以把球放回中圈才是对的行为。
3. 上半场由主队开球（`engine.js:662` 的 `_kickoff("home")` 是硬编码初值）
   ⇒ 下半场客队开球，符合惯例。

⚠ 两个必须遵守的约束（已写进代码注释）：
  · **只在 `fromMin === 46` 开球**。另一条触发路径 `state._simNeedsResync`
    （换人/换阵）**不能**开球 —— 否则用户在 60 分钟换个阵型会当场重新开球。
  · **顺序不能反**：必须先 `resyncSimAfterHalfTime`（把 `baseX/baseY` 镜像到新半场），
    再 `_kickoff` 吸附；反了会吸附到换边前的位置。

[4] 影响面与验证
================================================================================
· 改动只发生在**下半场开头**（`fromMin === 46`）那一帧，是一次性的位置吸附 + 开球。
  上半场（1–45 分钟）逐位不受影响；`_simNeedsResync` 路径不受影响。
· ⚠ **这是标准档行为改动**（改了下半场开头的球与球员位置）⇒ 下游决策路径随之改变，
  进球/beat 等护栏需重跑复核（见 [5]）。
· 探针：`scripts/_halftime-gk-swap-probe.mjs`（含现状/修复对照，可复跑）。
  它同时是一条**回归防线**：若将来有人把 `_kickoff` 那一步删掉，
  读数会立刻回到 ~100m / 十几秒。

[6] 一句话总结
================================================================================
「换边」把**目标位**瞬间翻过去了，却没把**身体**搬过去 —— 于是门将（和全队）
要自己跑 100m。修复 = 换边后按真实规则重新开球（`_kickoff`），
实测把门将距门从 97m 压到 4m、把 14.5 秒的空门窗口压到 0.1 秒。
