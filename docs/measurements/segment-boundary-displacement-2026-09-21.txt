## 判决

**签名 = 场景切换（剪辑），不是物理 bug。**
依据（skill `motion-artifact-diagnosis` Step 4）：

- 后三次切段**全队一起跳** —— 中位位移 14.3 / 24.0 / 35.0 m，
  是普通帧中位 **0.08 m** 的 **180~440 倍**；第 3 次 **26/26 个实体全体 >6m**。
- 「所有实体一起跳」= 换了场景，不是某个实体的运动学坏了。
- `sceneCut` 四次全为 `true`，与 `applySimSnapshot` 的设计一致：
  切段时**刻意关掉 relocate 缓动**（`if (sceneCut) entity._relocAt = 0`），
  用一次 260ms 淡场把这一跳讲成「换了条镜头」。

**但遮罩不够：`fadeOpacity` 四次恒为 `0.72`。**
`css/style.css` 的 `@keyframes mp-seg-cut-fade` 是
`0% { opacity: 0.72 } → 100% { opacity: 0 }`。
也就是说：**跳变发生的那一帧，遮罩最浓时也只有 72%**，
观众仍能看见 **28%** 的整体位移 —— 这正是用户报的「整队瞬移」。
而且它一路衰减到 0，后半程遮罩更薄。

⇒ **不要把这条判成「已修好」。** 场景切换的事实已确认，但「遮住」这件事没做到位。


## 顺带查出的一个真 bug（开球多闪一次）

第 1 条切段是 `t0 = 0.1`（**开球**），但它被判成了 `cut`、还闪了淡场。
按 `_enterSegmentTransition` 的设计注释，开球应当是 `mode='first'`、**不闪**：
「没有上一段则说明是本场第一次入场（开球），那是比赛开始而不是跳过了内容」。

**真因不是归档里写的「钩子打晚了」**（本探针在点 `#btn-sim-live` **之前**就装了钩子，
仍然抓到这条），而是 `js/matchview.js:1236` 的 finite 守卫失效：

```js
this._segLastEndSimT = null;          // 构造函数初值（line 277 / 1709）
...
const prevEnd = Number(this._segLastEndSimT);   // Number(null) === 0  ← 陷阱
if (!Number.isFinite(prevEnd) || !Number.isFinite(t0)) return { mode: "first" };
```

`Number(null) === 0` 且 `Number.isFinite(0) === true` ⇒ **守卫拦不住初值**，
于是 `gapSec = 0.1 - 0 = 0.1 ≠ 0` ⇒ 判成 `cut`，开球凭空多闪一次淡场。
（`undefined` / `NaN` 才会被拦住 —— 实测已确认。）

这条也**修正了** `docs/measurements/segment-cut-verify-2026-09-21.txt` 里
「`first=0` 是钩子打晚了」的解释，以及 `MODES: first=0 cut=2` 的成因。

⚠ 未修。这是修复方案要一并处理的一环，交接清单已列出。
