④-B「真正的继续看」实测（2026-09-22，v282）
============================================

这份文档回答什么
----------------
`docs/handoff-2026-09-22.md` §5 第一优先：**④-B 续播**。配方已由上一轮查实，
本轮**实现 + 实测**。要证明的核心承诺是**运行时行为**：

> 点「从 N′ 接着看」之后，**第一帧落在续播点附近，而不是 0′**。

静态断言（`reopened-match-notice-audit.mjs`）只能证明「按钮接线了」，
**证明不了这件事** —— 本仓库有「单测 17/17 全绿、浏览器里画面上什么都没发生」
的血例（进场动画，见 AGENTS.md ③）。

探针：`scripts/_match-resume-probe.mjs`（`npm run test:resume-browser`）
命令：`node scripts/_match-resume-probe.mjs 5`（目标 5′，约 4 分钟）


实现（`js/main.js`，**`js/match.js` 零改动**）
--------------------------------------------
1. 进度记录多存**模拟秒 `simT`**。
   `writeMatchProgress` / `setMatchMinute` / `refreshLiveHudFromState` 透传。
   ⚠ 45′/90′ 那几处收尾调用**不带** simT ⇒ 必须沿用上一次的值，不能抹成 null。
2. 模块级 `matchResumeSimT`：桥接器 `playHighlightPlanBridge` 段循环**开头**
   跳过 `t1 ≤ 续播点` 的段，复用现成的 skip 路径
   （`spec.onSkip(seg)` 记账 + `refreshLiveHudFromState(seg.toMin, seg.t1)`），
   但**不走**「⏩ 跳过平淡」横幅（一次长快进会刷出十几条噪声），
   改打一条专属的「⏩ 快进到你上次看到的位置（N′）」。
3. **首次真正渲染后**清掉 `matchResumeSimT`（不清会把整场都跳光）。
4. 重开弹窗加「从 N′ 接着看」→ `runMatch("live", { resume: true })`；
   `runMatch` 默认 `resume = false` ⇒ 用户自己点直播仍是既有「从 0′ 重演」语义。
5. 跨半场**不用特殊处理**（见下）。


为什么可行（上一轮查实，本轮照做）
----------------------------------
`js/match.js` 的 `simulatePeriodWithSim` 把**渲染**交给 `opts.playHighlightPlan`，
之后有一段兜底循环：flush 全部剩余线索 + 对每个分钟跑 `finishMinuteSideEffects`。
⇒ **一个段都不渲染也不会丢进球 / 体能 / 事件。**

### 三轮合起来说明什么

**「首帧 ≈ 续播点」是错的判据** —— 它只在续播点落在段边界时成立。
正确判据有两条：

1. **首帧不早于续播点**（允许 1 秒帧对齐误差）⇒ 看过的那段一点都没重看；
2. 与「从头重看」**对照组配对**：跳过量 ≥ 续播点的 90%
   （不写「≥ 续播点」：对照组首帧是 **0.1** 而非 0，精确比较会差这 0.1 秒而假红 ——
   实测差 0.1000000000032）。

判据 1 的依据是本仓 census 的**段间隔 129.5~956.8 模拟秒**：
续播点可能落在任意一段内部，能保证的只有「不早于它」。


跨半场
------
H2 续播时 H1 的段**全部**被跳过 ⇒ **没有渲染** ⇒ `matchResumeSimT` 保持非 null
一直带到 H2，正好继续跳过 46′ 之前的段。中途会停在**中场面板**等一次确认
（用户可顺手调整战术）—— 这是有意的，弹窗文案里已讲清：
「你上次在下半场，上半场会被快进 —— 中途会先停在中场面板一次，直接点继续即可。」

**跨半场实测**（第 3 轮阶段 5）：把续播点**合成**到 50′（3000 模拟秒）后
重开比赛 —— 弹窗按钮显示「从 50′ 接着看」、正文交代了中场面板；
点下去后 H1 整段走了续播跳过（专属横幅命中），**停在 HUD 45′ 的中场面板**等确认。

⚠ 为什么用**合成**续播点：真跑到 50′ 再刷新要多花好几分钟，而这里要验的只是
「续播点位于 H2 时桥接器 / 弹窗的行为」—— 它不关心这个 `simT` 是怎么来的。
记录的键仍取自真实记录（赛季/天/场次对得上）。


旧断言的前提变了 ⇒ 反向加强，不是放宽
--------------------------------------
v281 的 `reopened-match-notice-audit.mjs` 钉的是「**弹窗不得出现承诺续播的字样**」，
前提是「续播没实现」。本轮把前提取代了 ⇒ 断言**反向加强**为：

- 弹窗有 `#btn-reopened-match-resume`；
- 它由进度记录里的**模拟秒** `simT` 守卫（没有 simT 就不给按钮）；
- 它真的接到 `runMatch("live", { resume: true })`；
- 下半场续播时文案讲清「会先停在中场面板」；
- **桥接器真的跳过** `t1 ≤ matchResumeSimT` 的段，且**首次渲染后真的清掉**；
- 续播跳过复用现成 skip 路径（不另造一套）。

变异测试从 **7 项加到 10 项**（新增：接着看按钮不接线 / 桥接器不跳过 /
续播点不清空 / 进度不记模拟秒）。

`reopened-match-notice-browser-check.mjs` 里同一条旧断言也同步改成
「续播入口必须就是 `#btn-reopened-match-resume`（不是另造一个措辞相近的假按钮）」。


环境噪声（不当红）
------------------
三轮都出现过若干条
`http://127.0.0.1:<port>/js/<模块>.js :: net::ERR_CONNECTION_REFUSED`
（第 3 轮 6 条，`data.js` / `branding.js` / `finance-ledger.js` / `ui/finance.js` …）。
这是 `python -m http.server` 在 Playwright 一次性拉 90+ 模块时**偶发拒连**
（监听 backlog 溢出），与产品代码无关 —— 页面随后正常走到比赛界面、
`pageerror` 为 **0**。

⚠ 但它确实是**测试环境的固有噪声**，不是「已验证无害」：如果哪天 SW 预缓存
因为这类拒连而不完整，症状会是**离线时白屏**，本探针覆盖不到。
要根治得把探针的静态服务器换成带更大 backlog 的实现（本轮没做）。

探针因此只把 **pageerror**（真实 JS 异常）当失败，资源级失败单独打印（`REQFAILED`）。
