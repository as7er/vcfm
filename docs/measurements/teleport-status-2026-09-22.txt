「瞬移」现状复核（2026-09-22，用户问「是不是还没根本上改好」）
================================================================

结论先说
--------
**切段那一类已经压下去了**（跳变帧的遮罩是全遮，不是 0.72），
**运动战里的个体硬置实测 0 次**（150 秒 / 7942 帧，一帧不漏）。

但「根本」二字要拆开看：**是遮掉，不是消除** ——
切段本身 26 个实体一起跳 27~65 m，这是**剪辑**（设计），黑场只是把那一帧盖住。


一、实测（`scripts/_segment-boundary-displacement.mjs`，150 秒直播，真实 Chromium）
-----------------------------------------------------------------------------------
| 类别 | 次数 | 读数 |
|---|---:|---|
| **切段边界** | 4 | 26 个实体一起跳，中位 **27.1 / 29.4 / 32.7 / 65.0 m**；跳变帧 `fadeOpacity = 1` |
| **运动战里的个体硬置**（>6m、非切段） | **0** | 普通帧 P99 = **1.49 m** |
| **开球摆位** | 1 | 24.0 m（`simT=0.1` 首帧），被 canvas 层 2 秒进场动画盖住 |

- 「个体硬置」判据：`>6 m` 在相邻帧（`dt ≤ 0.35 s`）里不可能
  （6 m / 0.35 s ≈ 17 m/s 已经是短跑）⇒ 超过就是**硬置**。
- 探针读的是 `mv.players[].x/y` —— 那是 **`applySimSnapshot` 缓动之后的显示坐标**，
  所以「0 次」是**画面上**的结论，不是引擎内部的。
- 采样量：7942 sim 帧、4 次切段 —— **单场样本**，不是多场普查（见 §四）。


二、代码侧对上（三条都指向「已修」）
------------------------------------
1. **顺序对**：`_enterSegmentTransition()` 在 `applySimSnapshot(frames[0], …)` **之前**调用
   （`matchview.js:1215` 的注释就是这么写的）⇒ 遮罩类与跳变在**同一帧**生效。
2. **遮罩足**：`@keyframes mp-seg-cut-fade { 0% {opacity:1} 35% {opacity:1} 100% {opacity:0} }`
   —— **0% 就是全遮**。v276 实测峰值只有 0.72（跳变帧还有 28% 可见），**v277 已修**。
3. **`prefers-reduced-motion` 也遮**：写成静态 `opacity: 1` 而不是 `animation: none`
   （注释写明：`animation:none` 会停在初始 opacity，等于没有遮罩）。


三、AGENTS.md ⑤ 那条结论**已经过期**，要改
-------------------------------------------
⑤ 写的是：

> `_chooseAttackOffBallTarget` 的 drop 分支锚在球位、else 分支锚在固定阵型位，
> 两锚相距可达 **74 m**，每 0.42~1.32 s 重掷一次 ⇒ **81~90% 的跳变是硬置**。

**现在不成立**，两个原因：

1. **那说的是「目标」跳变，不是「位置」跳变。** 两个分支写的是 `a.ty`（**目标**），
   引擎按速度积分逼近目标 ⇒ **球员位置本来就是连续的**。目标重掷改变的是「往哪走」，
   不是「在哪」。⇒ 它不该被计入「位置硬置」。
2. **A2（v274，`A2_ANCHOR_BLEND = 0.65`）已经接在两条分支上**
   （`engine.js:4336` 与 `:4399`），把两个锚点折中，锚距本身也缩短了。

⇒ 本轮实测 7942 帧里**运动战 0 次硬置**，与「81~90% 硬置」直接冲突。
   以实测为准。


四、剩下的真实口子（诚实列出）
------------------------------
1. **遮 ≠ 消除。** 切段跳 27~65 m 是真的，只是被黑场盖住。
   如果用户介意的是「过渡时会黑一下 / 场景直接换掉」，那是**剪辑的固有代价**，
   不是 bug —— 要消除就得连续跟拍（也就是把跳过的平淡段也放出来）。
2. **`relocate()` 的武装条件仍然窄**：`adjacent && restartFrame && …`
   （`restartFrame = restartType || motionContext.discontinuity`）。
   - 死球搬运落在**段内**（`adjacent=true`）⇒ 缓动 ✓
   - 落在**跨段**那一帧（`adjacent=false`）⇒ 不缓动，但同帧有黑场遮罩 ✓
   - **两者都没覆盖的组合**：`gapSec === 0`（两窗相接 ⇒ `mode:"first"` ⇒ **不淡场**）
     时又发生死球搬运。**本轮没量到，但它是逻辑上剩下的口子。**
3. **样本只有一场。** 「运动战 0 次」是 150 秒单场的读数。要把它变成可依赖的性质，
   得跑多场（或把它做成常驻护栏）。**本轮没做。**


五、探针自己修掉的两个口径错（否则上表会读错）
----------------------------------------------
1. **判决行原先只看 `cuts`**，普通帧只记 `max` 不分类 ⇒
   「个别实体跳 **0 次**」会被读成「没有个体瞬移」，而普通帧 max 是 23.9 m。
   ⇒ 补了 `normalJumps` 采集 + 判决行输出。
2. **第一版扩展把开球摆位算成了「运动战个体硬置」**：首帧 `_relocLastSimT` 是 NaN
   ⇒ `sceneCut` 为真，但它在 `pendingCut` 之外，被我记进了普通帧
   （`pl_903` 24 m + 两名助理裁判 21/19 m）。
   ⇒ 采集条件补 `&& !sceneCut`。**那是摆位，不是瞬移。**


六、Gemini 那份文档逐条对照
----------------------------
| 它的条目 | 判定 |
|---|---|
| 1. 数据频率 vs 渲染帧率 / 缺 Lerp | ❌ **不适用**。本项目**有**插值/缓动层（`relocate`）。问题从来不是「没有 Lerp」，而是**该缓动时它没武装**（`restartFrame` 门槛）。 |
| 2. 插值目标突变 / 特殊事件直接重置坐标 ⇒ 用淡入淡出而不是硬拉 | ✅ **正中根因**，且比它更细：重置点有**两类**（死球搬运 / 跨段剪辑），**解法不同**（前者缓动、后者黑场）。它那条「一律淡入淡出」只对后者成立。 |
| 3. 动画状态与逻辑坐标脱节（Root Motion） | ❌ **不适用**。场上 22 人是 canvas 画的圆点，没有骨骼动画 / 根运动。 |
| 4. 浮点精度 / 像素对齐 / 镜头抖动 | ❌ **不是主因**。实测跳变量级 27~65 m（切段）/ 13 m（角球搬运），比浮点与亚像素噪声大 **6~7 个数量级**。 |

⇒ 它是一份通用清单，四条里只有第 2 条落在这里；而它的建议（淡入淡出）
   恰好是本项目**已经在做**的那一半。
