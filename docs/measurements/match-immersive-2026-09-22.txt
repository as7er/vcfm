沉浸模式（点空白球场隐藏全部 chrome）（2026-09-22，v284）
==========================================================

用户诉求
--------
「上面的比分固定模块太大了；**下面的功能区如果能在不使用的时候选择隐藏**会更好吧？」
（前半句已在 v283 用「比分条中列压成一行 + 控球条去留白」处理，
见 `mobile-match-chrome-2026-09-22.txt`；本条处理后半句。）


⚠ 为什么不做「N 秒无操作自动隐藏」
-----------------------------------
**会重蹈 v276 的坑。** v276 刚做完**全屏键可发现性**：控制条 6 个图标键
同色同尺寸、用户找不到 ⇒ 改成主题色高亮 + 开赛 toast 提示一次。
整条控制条自动隐藏，那个按钮**又找不到了**。

所以做成**用户主动切换**：点空白球场 → 全部 chrome 淡出；再点 → 恢复。
这是视频播放器的标准手势（用户不用学），且进入时给一次明确提示
（「沉浸模式 · 再点球场恢复控制」），不会出现「藏起来就回不来」。


实现（三处）
------------
| 文件 | 改动 |
|---|---|
| `js/matchview.js` | 新增 `onPitchTap` 回调；`hidePlayerCard()` 改为**返回是否真关掉了一张可见卡片**；点空白球场的处理器改**排除法** |
| `js/main.js` | 新增 `toggleMatchImmersive(force)`；`ensureMatchPitch` 接线；`openMatch` 里复位（沉浸是**当场**的一次性选择，不跨场次继承） |
| `css/style.css` | `.match-layout.mp-immersive` 隐藏 比分条 / 控球条 / 控制条；横屏媒体查询里补 `.fmm-match-body` 的高度覆盖 |

### 为什么必须补横屏的高度覆盖

横屏的 `.fmm-match-body` 高度公式是
`calc(100dvh - 58px - 2 * var(--fmm-shell-pad))` —— **58 写死了**。
控制条被 `display: none` 之后，不补这条覆盖的话：
**页面底下空一块，球场一个像素都不会变大**（`display` 与 `opacity` 的区别就在这里）。
补的规则特异性 0,6,0 > 原规则的 0,5,0，且写在后面。

### 为什么不能隐藏 `.mp-wrap`

进球横幅（`.mp-banner`）与场内字幕胶囊（`setCaption` 的 `captionEl`）
**都在 `.mp-wrap` 里** —— 它们是沉浸模式下**唯一还能报事件**的东西
（底栏 ticker 会跟着 dock 一起藏掉）。所以只隐藏三块 chrome，不碰 wrap。


🔴 顺带修掉一个**从写下起就没生效过**的处理器
----------------------------------------------
`matchview.js` 里这段（旧代码）：

```js
this.fieldEl.addEventListener("click", (e) => {
  if (e.target === this.fieldEl || e.target.closest(".mp-grass") || e.target.closest(".mp-lines")) {
    this.hidePlayerCard();      // ← 从来没有执行过
  }
});
```

真因在 CSS：`.mp-actors { position: absolute; inset: 0; z-index: 4 }`
**没有 `pointer-events: none`** ⇒ 它铺满整个球场，
空白处的点击 `e.target` **恒为 `.mp-actors`**，三个条件一个都不成立。

**修法**：`.mp-actors { pointer-events: none }` + `.mp-actors .mp-player { pointer-events: auto }`
（它是绘制容器，只有热区该接收点击），并把 JS 守卫改成**排除法**
（只挡掉明确「不是空白」的东西：球员热区 / 卡片 / 横幅 / 字幕 / 按钮）。
排除法比列举「哪些算空白」更不容易漏 —— **漏了就是功能静默失效**。

⚠ 这也解释了为什么沉浸模式第一版**完全点不动**。


实测（`scripts/_match-immersive-probe.mjs`，真实 Chromium）
-----------------------------------------------------------
| 视口 | 基线可见球场 | 沉浸后 | 增量 |
|---|---:|---:|---:|
| 800×295（横持真机等效） | **188.5** | **328.3** | **+139.8（+74%）** |
| 1440×1000（桌面） | 765.4 | 918.5 | +153.1（+20%） |

增量比事先估的 ~100px 大：因为同时发生了三件事 ——
控制条让出 58px、控球条让出 18px、**比分条不再遮挡 38px**。

断言全过（两个视口各一套）：
- 点空白球场 → 进入沉浸；比分条/控制条/控球条**都**隐藏；
- **可见球场真的变大**（不是只藏了东西）；
- 进入时给出「再点球场恢复控制」的提示；
- 再点一次 → 全部恢复，球场回到基线（±2px）；
- 沉浸后 `scrollX = scrollY = 0`；
- **点球员不会误触沉浸**（热区被正确排除）；
- 卡片开着时点空白 → 只关卡片、不切沉浸；
- `pageerror` 0。

截图：`.tmp-immersive/immersive-<视口>.png`


探针自己踩的四个坑（都不是产品问题，记下来免得重踩）
------------------------------------------------------
1. **取点落在浮层上**：第一版「找远离球员的空白点」只避开了球员，
   800×295 下取到 `(412, 29)` —— 那正落在**比分条浮层**里
   （比分条 y=2.4..40.5、`position: absolute; z-index: 30`），
   点击被浮层吃掉，探针报「点不动」。
2. **取到的球员站在浮层下面**：第一版直接取 DOM 里第一个 `.mp-player`，
   它正好被比分条盖住 ⇒ 点击落空，探针报「点球员没开卡片」。
3. **几秒前算好的空白点被走过来的球员占掉**：第 4 步（关卡片）点在了球员身上，
   `onPick` 的 `stopPropagation` 让球场处理器根本没跑 ⇒ 报「卡片没关掉」。
4. **Service Worker 首次接管会让页面自动刷新一次**
   （`index.html` 的 `vcfm-sw-reloaded-vN` 那条）⇒ 首屏装的 `window.__cap`
   钩子被冲掉，报 `window.__capReset is not a function`。

⇒ 1~3 都是**取点**问题，产品代码是对的。**通则：**
- **DOM 里「存在」的元素 ≠ 「点得到」的元素** —— 取点要把所有浮层减一遍，
  并用 `elementFromPoint` **复核**，且**每次点击前重新取**（实体在动）。
- **钩子要幂等**，并在「已经进到目标界面」之后再装一次（SW 会刷新）。

### 判据口径也要小心

「退出沉浸后球场回到基线」第一版比的是**相机 rect**，读到 202.2 vs 基线 188.5，
看着像没恢复 —— 其实相机带 `scale(1.28)` 预设，rect 被镜头动画带着变。
改用**布局盒**（`clientHeight`）后是 211 → 211，逐位相同。

「进入时给了提示」第一版只读某一瞬的 `#mp-caption` textContent ——
它是**全应用唯一**的字幕槽，开赛前后被「比赛开始！」「🌧️ 雨战」连续抢占，
同一轮里 900ms 采样命中、随后的轮询全 miss。
改成**记录 `setCaption` 调用序列**才得到确定性判据。实测序列：

```
["沉浸模式 · 再点球场恢复控制", "🌧️ 雨战", "沉浸模式 · 再点球场恢复控制", ...]
                    ↑ 被顶掉                    ↑ 1.5s 后的重试救回来了
```


已知遗留（本轮没处理）
----------------------
- **比分条浮层会挡住站在它下面的球员**：它 `z-index: 30`、横屏高 38px，
  球员走到球场顶部那一条时点不到（要点他就得先进沉浸模式把比分条藏掉）。
  本轮**没有**改 —— 改它要么缩小浮层、要么让浮层只在需要时出现，
  都是独立决策。
- 沉浸模式的进入提示与 v276 的「全屏键提示」共用 `#mp-caption` 同一个槽，
  首场开赛附近两者可能互相覆盖（实测截图上出现过一次）。
  只影响**首次观赛的第一场**，且再点一次球场即可恢复，未处理。
