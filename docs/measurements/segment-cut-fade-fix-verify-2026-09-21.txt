## 🔴 同一轮修掉的检查脚本自身缺陷（一度让 `verify.mjs` 必红）

首版 `segment-cut-fade-verify.mjs` 报 **7 项失败**，而当时**产品代码是对的**。
根因在检查自己的辅助函数：

```js
// 首版（错）
const start = src.indexOf(signature);      // ← 命中的是**调用点**
```

`_enterSegmentTransition` 在 `js/matchview.js:892` 被调用，**定义在 `:1212`**；
`_playSegmentCut` 在 `:1252` 被调用，**定义在 `:1257`**。
`indexOf` 命中调用点后，往后找的第一个 `{` 落在**别人**的方法上 ⇒ 断言去数了别人的花括号
（`[1]` 甚至报出「定义体长度 15 字符」）。

**修法**：锚在**行首缩进 + 签名 + `{`** 上（`/^[ \t]*<signature>[ \t]*\{/m`），
调用点以 `this.` / `=` 起头，天然被排除；并加「体长落在预期区间」**双保险**
（`> 500 && < 20000`），太小 = 抓错块，太大 = 吞了后文。修后定义体长度实测 **1949**（`_playSegmentCut` 为 399）。

**可迁移教训**：用 `indexOf(签名)` 定位**定义**不可靠 ——
「名字第一次出现的地方」几乎总是**调用点**。
先例见 `AGENTS.md` 里那条「用固定长度窗口截源码做断言 = 假通过的常见来源」：
同一个坑还有**假红**这一面，而假红同样有害 —— 它挂在 `verify.mjs` 上，
下一个人要跑 43~57 分钟才发现红的是检查自己。
