# 射门频率标定（2026-09-13）

## 结论

`js/sim/engine.js` 四处改动，把标准档 24 场的射门从 **30.63 → 26.25 次/场**（双方合计，
真实约 26），转化率 **9.5% → 10.3%**（真实约 11%），九项真实性护栏全绿。
`STANDARD_PROFILE_REFERENCE_24` 随之有意刷新。

## 起点：上一轮的前提是错的

上一轮会话认定「当前 90 分钟 65 次射门，需降至 45%」，并据此收缩射门区、缩短全队冷却。
这个数字来自 `scripts/shot-interval-reliable.mjs` 那条浏览器探针，它有三个独立缺陷：

1. **样本量**：3 场 × 6 分钟 = 18 分钟比赛时间；`match-realism-audit.mjs 24` 是 2160 分钟，差 120 倍。
2. **采样偏置**：观察窗口固定在开场 0–6 分钟，而记录到的射门时刻密集落在
   00:21 / 00:26 / 00:29 / 00:41 / 00:49——开球段射门率显著偏高，只采这一段会系统性高估。
3. **折算公式错误**（该文件 120–121 行）：
   ```js
   const shotsIn90Min = (5400 / avgInterval) * (shotsPerMatch / (OBSERVATION_TIME / 1000 * 2));
   ```
   `5400 / avgInterval` 已是 90 分钟折算值，后面又乘了一个量纲不成立的因子。

该探针实际上从未成功运行过：它等待 `window.__simEngine`，而 `sim-viewer.html` 暴露的是
`window.eng`，`page.waitForFunction` 必然 30 秒超时。

**教训：射门/传球这类频率指标一律用 `node scripts/match-realism-audit.mjs 24` 量，
不要用 sim-viewer 挂钩子观察几分钟。**

## 护栏算术决定了修法次序

基线 24 场：射门 30.63、进球 2.92、转化率 9.5%。真实英超约为 26 次 / 2.85 球 / 11%。
失真不是单纯「射门太多」，而是**射得多、进得少**。由此：

| 若只压缩射门量（转化率不变） | 进球 | 判定 |
|---|---|---|
| 28 | 2.67 | 勉强 |
| **26** | **2.48** | **跌破护栏下沿 2.5** |
| 24 | 2.29 | 破 |

| 若要保住进球 2.92 | 所需转化率 | 相对提升 |
|---|---|---|
| 射门 28 | 10.4% | +9% |
| **射门 26** | **11.2%** | **+18%** |

所以只能**先提机会质量、让射门数跟着回落**，不能直接调低决策概率。

### 被否掉的两个方向

- **收缩 SHOOT_ZONE**（core 28→26、wing 22+6→18+4、mid 24→22、other 20→18）：
  把射门推到禁区内，禁区外占比压到 22.9%，跌破护栏下沿 25。已还原。
- **缩短全队冷却**（300+rand·180 → 180+rand·90）：射门**升**到 34.13、转化率掉到 8.2%
  （破护栏）。该项是射门总量的主导旋钮，方向与目标相反。已还原。

这两处与另外四处合在一起时互相补偿，净效果是射门不降反升——各自单独度量才看得出归因。

## 采纳的改动（`js/sim/engine.js`，4 处）

```js
// shootQuality：角度权重与距离持平，防守压力影响加重
(0.5 * distF + 0.35 * angF) * (0.5 + finBias) * (1 - pressure * 0.25);
→ (0.45 * distF + 0.45 * angF) * (0.5 + finBias) * (1 - pressure * 0.35);

// shootThresh：整体上移 0.02
core ? 0.24 : isWing ? 0.26 : isMid && dGoal > 16 ? 0.28 : 0.32
→ core ? 0.26 : isWing ? 0.28 : isMid && dGoal > 16 ? 0.30 : 0.34

// rangeBonus
dGoal >= 9.5 && dGoal <= 22 ? 0.32 : dGoal < 9.5 ? 0.1 : 0
→ dGoal >= 9.5 && dGoal <= 22 ? 0.15 : dGoal < 9.5 ? 0.08 : 0

// shootDecisionP
clamp(0.07 + shootQuality * 0.18 + rangeBonus + roleShoot * 0.05 + (setPieceChance ? 0.12 : 0),
      0.03, setPieceChance ? 0.64 : 0.56)
→ clamp(0.03 + shootQuality * 0.08 + rangeBonus + roleShoot * 0.03 + (setPieceChance ? 0.08 : 0),
        0.02, setPieceChance ? 0.35 : 0.28)
```

`SHOOT_ZONE` 与 `_teamShotUntil` 保持原值。
