# 无球跑位目标：四层管线的逐层归因，与租约判据缺陷

> 2026-09-19。起因：评估用户上传的 FM-like 设计文档时，怀疑「无球跑位机制之间缺仲裁层」。
> 量测后**假设被推翻**，但查出了另一个更明确的缺陷。
> 探针：`scripts/_offball-layered-attribution-probe.mjs`
> 读数：`docs/measurements/probe-offball-layered-attribution-2026-09-19.txt`

## 一、先纠正一个假设

评估文档时我提出：无球跑位的队形锚点 / 集体防守补位 / 压迫 / 无球目标
**四个机制各自都对，但没有一处做"哪个更有价值"的横向比较**，因此缺仲裁层。

**实测推翻了它。** 四个机制**不是并行的独立决策**，而是一条**严格串行的管线**，
每层修改同一个 `tx/ty`：

| 层 | 函数 | 触发 | 作用 |
|---|---|---|---|
| — | `_thinkAttackOffBall(a)` | 节流 0.42~1.32s | 生成初始目标 |
| 1 | `_applyAttackTactics(a)` | 紧随其后 | 宽度缩放 → 相位拉拽 → 纵深位移 → 队形锚点 |
| 2 | `_commitOffBallTarget(a)` | 紧随其后 | **租约判定** → 防拥挤分层 → 越位线投影 |
| 3 | `_separateSupportTargets()` | 每 tick 一次（全体定稿后） | 横向松弛（Gauss-Seidel） |

调用点：`engine.js:2106-2108`（层 0/1/2）与 `engine.js:1884`（层 3）。

## 三、大位移的真正来源：租约判据缺陷（🔴 真缺陷）

**每一个 ≥8m 的大位移（1,332 例）都是 `held` 造成的，无一例外。**

```
held 样本              1,561 个（占 0.97%）
被保留旧点的年龄        中位 0.90s   p90 1.10s   max 1.50s
租约把球员按住的距离    中位 19.18m  p90 35.06m  max 73.16m
其中按住幅度 ≥8m 的     1,332        ← 占大位移的 100%

对照：非 held 样本净位移  中位 0.00m   p90 0.00m   max 5.99m
```

**非 held 样本的最大位移只有 5.99m** ⇒ 正常的目标更新**从不**产生大位移。

### 机制

`js/off-ball-movement.js:101-130` 的 `holdPrevious`：

```js
const sameContext = !!previous && previous.phase === phase && previous.ownerId === ownerId;
const leaseActive  = sameContext && finite(now) < finite(previous?.until, -Infinity);
const holdPrevious = !urgent && leaseActive && targetChanged && reversal &&
                     oldTargetRemaining >= config.oldTargetRemainingMetres;
```

四个条件同时满足 ⇒ **原样返回 1.5 秒前的旧坐标**（`decision: "held"`）。

在一次快攻里这四条件**天然全部成立**：

1. `leaseActive` —— 节流中位约 0.8s < `leaseSeconds` 1.5s ⇒ 几乎每次重算都落在租约内；
2. `targetChanged` —— 球推进了 60m，新旧目标相距 ≥5.5m；
3. `reversal` —— 新目标在旧目标的相反方向；
4. `oldTargetRemaining` —— 球员离旧点还很远（因为球早跑了）。

⇒ **球员被按在 1.5 秒前的、已被球的发展淘汰的位置上。**

### 为什么这是判据缺陷，不是设计缺陷

租约的设计意图（`:1590` 注释）是**防折返** —— 阻止球员在两点间来回摇摆。
意图正确。但判据**只看"方向是否翻转"，不看"球是否已经跑远"**。

`sameContext` 也只检查 `phase` + `ownerId` 是否相同：**同一队仍在进攻（ownerId 不变）
但球已推进大半场**时，`sameContext` 依然为 true，租约照常生效。

⚠ **一次快攻中球推进 60m 是完全正常的**，此时"不折返"恰恰是错的 ——
球员**必须**改变目标跟上进攻。

（另：132 例呈现「纵向 ≥30m 且横向 ≤5m」的镜像指纹 —— 那是球场两端之间的对跳，
同一个根因的极端表现，**不是中场换边**：`attackDir()`（`engine.js:792`）
是硬编码常量，引擎里不存在换边。）

## 四、这次量测的边界（不要过度解读）

- **未验证**：租约在其他场景（阵地战、角球、界外球）是否也可能误保留。
- **未验证**：`held` 的 0.97% 里，有多少真的造成了"看起来不对"的画面 ——
  1332 例 / 6 场 ≈ **每场 222 例**，但其中多数可能球员本就离旧点很近、
  按住无感。**只有 132 例的镜像对跳是明确可见的。**
- **差异档未测**：本次全队属性同值（能力 15）——
  按项目方法论，**同值档会抹掉"球星 vs 普通"的差异**，若要验证
  「高水平球员是否更少被错误按住」必须另跑差异档。
- **本探针未改动引擎任何一行**，只包装四个方法读出进入/离开时的坐标。

## 五、下一步（尚未执行，需用户拍板）

修 `holdPrevious` 的判据，候选方向：

- **(A)** 加「球是否已明显偏离旧目标」的条件 —— 旧目标值不值得保留，
  取决于球相对旧点的位置，而不是只看球员自己；
- **(B)** 缩短 `leaseSeconds`（1.5s → 更小）—— 治标，且会让防折返失效；
- **(C)** 在 `sameContext` 里加入「球位移量」—— 球推进超过阈值即视为上下文已变。

⚠ **无论选哪个，都必须先给「租约命中率」补护栏并做噪声标定** ——
本项目已多次吃过「先改后标定」的亏（见 `AGENTS.md` 的护栏纪律）。
