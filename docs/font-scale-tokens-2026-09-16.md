# 字号令牌化（2026-09-16）

> 纯表现层：`css/style.css` / `js/main.js` / `index.html` 三处共 **374 个
> `font-size` 字面值**收敛到 **14 个 `--fs-*` 令牌**。没有改任何机制、数据或模拟。
>
> ⚠ **先说结论里最要紧的一条**：这是一次**可维护性**改动，**不是可见的美化**。
> 详见 §4 —— 我上一份调研把它的视觉影响说大了，这里更正。

## 1. 改前的量

| 指标 | 数值 |
|---|---:|
| `font-size` 声明总数 | 337（CSS）+ 33（`main.js` 内联）+ 11（`index.html` 内联） |
| **不同字面值** | **45 个** |
| 取值范围 | 8.00 px – 28.80 px |
| 低端密度 | 8.00 / 8.32 / 8.64 / 8.80 / 8.96 / 9.28 —— **每 0.2–0.3 px 一档** |

45 个值不是设计出来的，是长期「这一处再小一点点」累积的漂移。两个典型症状：

- 同一个元素在不同上下文里有两个值：`.fm-sb-score` 同时存在 `1.45rem`（`:4657`）
  与 `1.55rem`（`:2437`）。
- 相邻档位差 < 0.5 px，肉眼分不出，但代码里是两套值：
  `0.85rem`(13.60) / `0.86rem`(13.76) / `0.88rem`(14.08) / `0.9rem`(14.40)。

## 2. 令牌定义（14 级）

写在 `css/style.css` 的 `:root` 里，**只在 `:root` 定义一次**：

```css
--fs-4xs: 0.5625rem;  /*  9px  极小角标（球衣号、微型徽标） */
--fs-3xs: 0.625rem;   /* 10px  角标 */
--fs-2xs: 0.6875rem;  /* 11px  次要标签 */
--fs-xs:  0.75rem;    /* 12px  表格/密集列表 */
--fs-sm:  0.8125rem;  /* 13px  次要正文 */
--fs-base:0.875rem;   /* 14px  正文 */
--fs-md:  0.9375rem;  /* 15px  强调正文 */
--fs-lg:  1rem;       /* 16px  卡片标题 */
--fs-xl:  1.0625rem;  /* 17px  次级区块标题 */
--fs-2xl: 1.125rem;   /* 18px  区块标题 */
--fs-3xl: 1.25rem;    /* 20px  卡片主行（如「主队 vs 客队」） */
--fs-4xl: 1.375rem;   /* 22px  页面标题 */
--fs-5xl: 1.5625rem;  /* 25px  大数字 */
--fs-6xl: 1.75rem;    /* 28px  比分等展示数字 */
```

**为什么是 14 级而不是我原先建议的 6 级**：定级方式不是「先定一个理想标尺再把代码
塞进去」，而是**贴着现有密集簇定级**，让绝大多数声明只移动 ≤0.5 px。压到 6 级会把
卡在 **17 px 圆圈里的球衣号**（原 `0.5rem` = 8 px）和**手机球场上的球员名**
（原 `0.52rem` = 8.32 px）顶到 10 px 以上而撑破容器。宁可多几级，也不制造溢出。

`--fs-*` 不在 light 主题块里重复定义：字号与主题无关（§5.1 有静态证明）。

## 4. ⚠ 更正：这是可维护性收益，不是可见的美化

我上一份调研写「一页 11 种字号是最刺眼的『不专业感』」，**这个说法把视觉影响说大了**。

原因是探针统计的是 `getComputedStyle().fontSize` **四舍五入后的整数 px**，而 45 个
字面值本来就落在同样的整数桶里：`0.85rem`(13.60) / `0.86rem`(13.76) /
`0.88rem`(14.08) / `0.9rem`(14.40) 全都渲染成 14 px。

**逐页实测（改前 → 改后）**：

| 页面 | 页内字号种类数 | 最高频字号 |
|---|---|---|
| desktop/dashboard | 11 → **11** | 14px ×40 → 14px ×39 |
| desktop/squad | 8 → **8** | 14px ×434 → 14px ×434 |
| desktop/tactics | 10 → **10** | 14px ×104 → 14px ×104 |
| desktop/competitions | 8 → **8** | 14px ×945 → 14px ×945 |
| phone/squad | 8 → **8** | 13px ×419 → 13px ×419 |
| phone/transfer | 8 → **8** | 13px ×328 → 13px ×328 |

**种类数几乎不动**，因为 45 个值本来就是同一个整数渲染尺度的亚像素漂移。

所以这次改动真正的价值是：

1. 45 个散落字面值 → 14 个**有名字、有用途注释**的令牌；
2. 以后调字号是改一行 `:root`，而不是 grep 374 处；
3. 顺带把 `0.55rem`–`0.62rem` 那批 8.8–9.9 px 的角标统一到 9–10 px。

**真正可见的美化仍在待办里**（调研文档 §B 的 B1–B7：桌面开赛前球场细条、
手机顶栏占 25.7% 屏高、位置双标签冗余、三套球场画法…）。

## 5. 验收

### 5.1 静态核查（不依赖浏览器）

| 检查 | 结果 |
|---|---|
| 非 `font-size` 的改动 | CSS 只有新增的令牌定义与注释；`main.js` **零处**；`index.html` 零处 |
| 残留数字字面值 | **0**（仅剩 `0.85em` 与两个 SVG 用户单位） |
| `data-theme="light"` 规则体内的 `font-size` | **0 处** |

最后一条是**浅色档不必重跑**的依据：字号与主题无关，浅色块只覆盖 41 个自定义属性
+ `color-scheme`。上一个改动（简报 2 px）我跑了两个主题，因为那次改的是颜色相关
（`flex` 与主题无关但也一起验了）；这次可以用静态证明省掉一半时间。

### 5.2 逐页普查（`_ui-survey.mjs`，12 桌面页 + 5 手机页）

- `pageErrors: []`
- 横向溢出**没有变差**：phone/squad 307 → 302、phone/transfer 609 → 568、
  phone/table 78 → 78、其余不变
- 页高变化 ≤4%

⚠ **口径限制**：`_ui-survey.mjs` **不固定随机种子**（每次 `新建游戏` 内容不同），
所以 `panelH` 的前后差里混着内容差，**不能当作字号改动的效应量**。
可靠的是字号直方图与位移表。

### 5.3 端到端与比赛屏布局

| 检查 | 结果 |
|---|---|
| `browser-e2e.mjs` | **退出 0**（含 `desktop/mobile overflow`） |
| `_briefing-layout-probe.mjs`（深色档 × 5 视口） | **退出 0**；`formStrip.issues` 全空、`overflowX 0`、`overlapCount 0`、`pageErrors []` |
| 比赛屏 `<11px` 元素数 | **50 → 31** |

**⚠ 「50 → 31」必须如实解读**，它**大部分是阈值效应，不是可见的改善**：

| 元素 | 改前 → 改后 | 性质 |
|---|---|---|
| `form-cell` win/loss/draw（五场状态方块） | 10.88 → 11，**10 个跨过判定线** | 只动 0.12 px，肉眼不可见 |
| `team-talk-desc` | 10.88 → 11，5 个跨线 | 同上 |
| `fm-sb-comp` / `mp-fmm-speed` | 10.88 → 11，各 1 个 | 同上 |
| `mp-bench-dot`（替补席号码点） | **8 → 9，16 个** | **真实 +1 px** |
| `mp-official` 裁判/助理 | 9.5 / 10.5 → 10 | 真实 +0.5 / −0.5 px |
| `mp-end-label` | 8.8 → 9 | 真实 +0.2 px |
| `mp-bench-side` / `fm-sb-live` | 9.92 → 10 | 真实 +0.08 px |
| `muted` | 10.4 → 10 | 真实 −0.4 px |

即：**8–10.4 px 那一档整体上移了 0.2–1.0 px**（16 个替补席号码点是 +1 px，
是这批里唯一算得上可感知的），而 10.88 px 那一档只是刚好越过探针的 11 px 线。
所以「31 个仍然 <11px」里包含 15 个 9 px 的替补席号码点——它们卡在 17 px 圆圈里，
**本轮有意不动**（见 §2）。

### 5.4 缓存

`sw.js` 的 `CACHE`、`index.html` 的 `CURRENT_CACHE`、三处 `?v=`、
`vcfm-sw-reloaded-v` 同步升 **v259 → v260**。
