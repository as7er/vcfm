## 4. 🔴 第一优先：用户点名的两条瞬移复现（**已定位、未修**）

用户原话：
> 开角球的时候，球员还是会**瞬移到目标站位**；中场暂停回归阵容站位的时候也是瞬移。

### 4.0 为什么上一轮「实测 0 次」没抓到它们
`_segment-boundary-displacement.mjs` 的判据是**位移**（>6m）。
`relocate()` 的缓动是 **ease-out cubic**（`e = 1-(1-u)^3`，`u` 每帧只走 0.1/0.7≈0.143
⇒ **首帧就走掉 36%**），一次 15m 的摆位首帧只有 **5.4m** —— **落在我原来的 6m 门槛下面**。
⇒ 整类被漏掉。**判据要换成速度**（或「位移 > 2m 且 dt ≥ 0.08」），本轮已改进探针。

### 4.1 中场「回归阵容站位」= **硬吸附，缓动根本没武装**（根因已确证）

链路：
```
applyHalfTimeSwap(state, 46)            // js/match.js:1472
  → resyncSimAfterHalfTime(state)       // 只改阵型锚点 a.baseX/a.baseY
  → eng._kickoff("away")                // js/match.js:1499  ← 吸附 22 人
```

`_kickoff`（`js/sim/engine.js:8253`）里 `a.x = a.baseX; a.y = ...` —— **硬置**。
而画面侧的 `relocate()` 武装条件是
`adjacent && restartFrame && !_relocAt && (距离 > 门槛 || followOwner)`，
其中 `restartFrame = sim.ball?.restartType || sim.motionContext?.discontinuity`。

🔴 **`_kickoff` 刻意不设 `ball.restartType`**（`engine.js` 里那段注释写明了原因：
`restartType` 有 **8 处消费者**，含 `box-defending-audit` 的 `crowdedPairs`（上限 14、干净基线 12、
**余量只有 2**）、`edge-rules-audit` 的等值断言、`_queueBallAction:1155` 的提前返回）
⇒ **`restartFrame` 为假 ⇒ `relocate()` 永不武装 ⇒ 22 人一起硬瞬移。**

⚠ `_kickoff` 是 **2026-09-20 为修「换边后门将回位太慢（13.4s，球门空着）」才加进中场路径的**
（见 `js/match.js:1479~1499` 的注释）——**用一个瞬移换掉了另一个问题**，当时没从画面侧补缓动。

### 4.2 开角球「瞬移到目标站位」

链路：`_restart("corner", ...)`（`engine.js:7635`）里对球员**直接写 `a.x/a.y`**
（`engine.js:7882~7928`，按 `attackBoxX/Y` / `defendBoxX/Y` / `edge` 分槽硬置）。

**与中场不同：`_restart` 会设 `b.restartType = type` ⇒ `restartFrame` 为真。**
所以只要 `adjacent` 成立（段内），`relocate()` **会**武装 ——
本轮实测（220 秒 / 7892 帧）**角球类帧 1316 个，>2m 的只有 31 帧、>5m 的只有 1 帧**
（那 1 帧是开球摆位）。⇒ **段内的死球摆位确实被缓动了。**

**所以角球的瞬移只可能来自这两条之一，必须接着量：**
- **(a) 角球恰好落在「段首」**：`_enterSegmentTransition` 判 `mode:"cut"` 时
  `applySimSnapshot` 的 `sceneCut` 为真 ⇒ `entity._relocAt = 0`（**缓动被显式关掉**）
  ⇒ 硬切。**而角球正是高光窗的常见开头**，这条概率不低。
  本轮 220 秒样本里**没抓到「角球 ∧ 段首」的组合**，所以还没定论。
- **(b) 缓动只有 700 毫秒「模拟秒」**（`RELOCATE_MS = 700`）。
  若直播播放倍速 >1，0.7 模拟秒在真实时间上更短 ⇒ 眼睛看到的就是「一闪到位」。
  **这条要查 `main.js` 的直播倍速**，本轮**没查**。
