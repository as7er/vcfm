# 标准档的真实进球率，以及 24 场门限在下限处的分辨率（2026-09-15）

> 这是**预先存在**的读数性质问题，与任何候选补丁无关。本轮之前它只是
> AGENTS.md 里的一句「标准档真实进球率贴着 2.5 下限（要判定需 ≥96 场）」。
> 本轮把它量完了。

## 1. 结论

1. 标准档的真实进球率是 **2.7083 球/场**（384 场，95% 双侧 CI **[2.526, 2.891]**，
   单侧 95% 下界 2.555）。**下限 2.5 被排除**——引擎并不真的低于信封。
2. 但**门限用的那 24 个固定种子几乎没有分辨率**：16 个彼此不重叠的新鲜 24 场窗口里，
   **4 个（25.0%）跌破 2.5**。用本轮估出的参数算，理论值是 28.8%，与观测一致。
3. 因此 `verify --full` 报出的 `standard 2.75` **不能读成「离下限还有 0.25 的余量」**。
   它是「固定样本恰好落在真实均值附近」，而同一个引擎换一组种子有约 1/4 的概率不过关。
   固定种子让它是确定性的（不会随机翻红），但也让它对下限几乎没有检出力。
4. 方差**全部来自转化率，不来自射门供给**。8/16 个窗口的射门数只差 34 脚
   （633~667，±2.5%），转化率却从 7.7% 摆到 12.2%（4.5 pt，相对 59%）。
   要动进球率，通道是转化率；机会创造量已经被控得很紧。

## 2. 方法

用仓库里既有的 `scripts/_realism-seed-window.mjs` 把审计的种子窗口整体平移 24 的整数倍，
跑 16 个互不重叠的窗口，每个窗口 24 场等强对阵，共 **384 场**。

```bash
node --import ./scripts/_realism-seed-window.mjs \
  scripts/match-realism-audit.mjs 24 standard equal-only --seed-offset=24
```

三个口径要点：

- **`_realism-seed-window.mjs` 是 `--import` 预载模块，不是入口。** 它自己只注册
  `registerHooks`（把 `165000 + match` 换成 `165000 + offset + match`，并把 `console.log`
  换成带 `rawSample` 的版本），文件到 hook 注册就结束了。**必须把它当预载、把审计当入口**，
  `--seed-offset=N` 放在最后当位置参数。直接 `node scripts/_realism-seed-window.mjs
  --seed-offset=24` 会静默什么都不做、**退出码 0、输出 0 字节**（本轮先踩了一次）。
- **`equal-only` 只跑等强那一半。** 审计里 `strongMatches = equalOnly ? 0 : max(16, matches)`，
  所以加上它每个窗口从 48 场降到 24 场，且跳过的 `strongVsWeak` 断言本来就有 `if (!equalOnly)` 守卫。
- **`rawSample.totals` 天然只统计等强场次。** 强强对阵那一圈（`match-realism-audit.mjs:300-309`）
  只累加 `engine.score`，不写 `totals`。所以 `totals.goals` 就是等强进球数，
  `perMatch.goals = totals.goals / matches` 正是被 2.5 门限管的那个数。

## 4. 统计汇总

| 量 | 值 |
|---|---|
| 总进球 / 场次 | 1040 / 384 |
| 真实进球率 | **2.7083** |
| 窗口均值：最小 / 中位 / 最大 | 2.083 / 2.792 / 3.25 |
| 窗口均值 sd | 0.3727 |
| 隐含每场 sd | **1.826**（Poisson 参照 1.646，过度离散 1.11×） |
| 384 场合计均值的 SE | 0.0932 |
| 双侧 95% CI | **[2.526, 2.891]** |
| 单侧 95% 下界 | 2.555 |
| 跌破 2.5 的窗口 | **4 / 16 = 25.0%** |
| 越过 3.3 的窗口 | **0 / 16** |
| 总转化 | 10.00% |

每场 sd 1.826 是可信的：真实足球的每场进球 sd 约 1.7–1.8，所以**过度离散程度本身是真实的**，
不是引擎的伪影。它同时意味着 24 场样本的均值 sd 约 0.37——**和整个信封半宽（2.5~3.3 的一半
0.4）是同一个量级**。这就是为什么 24 场在下限处没有分辨率。

### 4.1 一个诚实的过程记录

先只跑 8 个窗口（192 场）时读数是 **2.6771，CI [2.398, 2.956]**——**区间仍然包含 2.5**，
方向判不出来。补到 16 个窗口才收敛到 2.7083。两次点估计差 0.031，正好落在
8 窗口的 SE（0.142）之内，属于正常抽样波动，但它说明**「判定方向」这件事本身需要
比直觉更多的样本**：192 场还不够。

### 4.2 需要多少场才够

- 让「新鲜 24 场窗口跌破 2.5」的概率降到 5%（单侧）：需要约 **208 场**。
- 双侧 95% 排除 2.5：需要约 **296 场**。
- 门限现在跑 24 场（标准档 24+24 约 10 分钟），所以把门限样本加大到 200+ 场
  并不现实。

## 5. 该怎么读这个门限

**不要把 2.5 当成「余量 0.25」的信号。** 正确的读法有三种，本项目取第三种：

1. ~~放宽下限~~ —— 禁止。信封编码的是真实世界的合理性，不是给改动让路的旋钮。
2. ~~刷新冻结参考~~ —— 禁止，且这里也没有参考过期的问题。
3. **把固定种子的 24 场门限当成回归绊线，而不是分辨率仪器。** 它与本轮运动完整性
   护栏是同一类东西（见 `sim-change-validation` 技能 Step 4 的功效反向用法）：
   - 它**能**抓住「进球率整体掉了 0.2 以上」这种量级的回归；
   - 它**不能**判断「2.5 这个下界到底有没有被真实越过」；
   - 由于种子固定，它是确定性的——**不会随机翻红，但也因此对下限几乎不敏感**。

配套的可操作结论：**如果一个候选在新种子窗口上跌破 2.5，先量那个窗口本身是不是低抽样**，
再去查机制。本节的 16 个窗口给出了这个基线：同样的引擎，换 24 个种子就有 25% 的概率跌破。

## 6. 方差来自哪里：转化率，不是射门量

这是本轮最有用的一条，因为它把「进球率」这个目标拆成了两个通道：

| 通道 | 16 个窗口的极差 | 相对幅度 |
|---|---|---|
| 射门数 | 633 ~ 667（34 脚） | **±2.5%** |
| 转化率 | 7.7% ~ 12.2%（4.5 pt） | **59%** |
| 传球数 | 1041 ~ 1064（23 脚） | ±1.1% |
| 传中占比 | 5.0% ~ 5.6% | ±6% |

射门供给（646±20）几乎是个常数，进球率的全部摆动都发生在「射门 → 进球」这一段。
所以：

- 若将来需要把进球率往某个方向推，**通道是转化率（射门质量 / 门将扑救 / 近距离把握）**；
  去动机会创造量只会破坏一个本来很稳的量。
- 反过来说，**「机会太少」不是标准档进球率偏低的解释**——射门数一直稳定在 26.9/场。
  这与前几轮把「跑位候选吃掉进球」归因到**近距离射门**的结论方向一致
  （见 `docs/movement-release-2026-09-15.md`）。

## 7. 本轮不做什么

- **不动信封的任何上下界**（2.5 / 3.3 保持原值）。
- **不动冻结参考**（`STANDARD_PROFILE_REFERENCE_24` 保持原值）。
- **不改 `verify.mjs` 里 realism 入口的场数**（保持 24）。把门限样本加大到 200+
  场需要用户明确决定，且会把 `verify --full` 的时长推高一个数量级。
- **不因为本轮发现就去调引擎**。本轮只回答「真实值是多少、门限有多少分辨率」，
  没有证据表明 2.71 需要被改动。

## 8. 复现

```bash
# 单个窗口（offset 必须是 24 的整数倍）
node --import ./scripts/_realism-seed-window.mjs \
  scripts/match-realism-audit.mjs 24 standard equal-only --seed-offset=192

# 本轮 16 个窗口
for off in 0 24 48 72 96 120 144 168 192 216 240 264 288 312 336 360; do
  node --import ./scripts/_realism-seed-window.mjs \
    scripts/match-realism-audit.mjs 24 standard equal-only --seed-offset=$off \
    > .tmp-continuity/primary-slot/goal-windows/w$off.log 2>&1
done
```

原始日志：`.tmp-continuity/primary-slot/goal-windows/w{offset}.log`。

**解析坑**：上面用了 `2>&1`，所以跌破门限的窗口日志里，JSON 后面会跟着
`AssertionError` 的调用栈；`JSON.parse(text.slice(indexOf("{"), lastIndexOf("}") + 1))`
会因此抛 `Unexpected non-whitespace character after JSON`。要用**括号配对扫描**取第一个
完整对象（`_expanded-realism-analysis.mjs` 里有现成实现），不要用 `lastIndexOf`。

**口径说明**：这 384 场跑在**已落地的引擎**上（含 2026-09-15 的中场前插名额修复）。
该修复在标准档只在「评分最高的中场被罚下」时改变行为，在门限固定样本上的聚合逐位相同；
标准档红牌 0.08~0.50/场，其中只有一部分是中场、且只有评分最高者才触发，
故它对这 384 场的影响远小于本节自身的抽样噪声（SE 0.093）。
