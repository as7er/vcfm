# 颜色去重（2026-09-16）

> 纯表现层：`css/style.css` 一处文件、**82 处**改动。没有改任何机制、数据或模拟。
>
> ⚠ **本轮的诚实边界**：只做了**可证明是「无操作」**的那一类去重（82 处）。
> 剩下 **313 处基础作用域**的字面值**有意没动** —— 因为项目的**每一个令牌都随主题

> 不是去重。理由与后续方案见 §4。

## 2. 为什么颜色比字号难：每个令牌都是主题相关的

字号只有一套值，所以「字面值 → 令牌」总是保值的。颜色不是：

```
--primary  深色 #3d8bfd   浅色 #2563eb
--warn     深色 #e6b450   浅色 #a16207
--border   深色 #2a3650   浅色 #c5d0e3
```

**26 个颜色令牌全部随主题变化**。所以一条写在基础作用域（两主题都生效）里的
`color: #3d8bfd`，换成 `var(--primary)` 之后在浅色下会变成 `#2563eb` ——
这是**真实改变**，不是去重。

架构上这是有意为之：基础规则按深色写，浅色由
`/* ===== 日间模式全面补丁 ===== */`（`css/style.css:7252`）那一节逐条覆盖。
`css:2918` 有一条注释正好说明了这个模式：

> 浅色主题：上面整块是按深色面板配的（半透明深底 + 近白正文 + 亮黄强调）。
> 叠到白底上底色变浅，#e2e8f0 正文和 #fde047 黄标题就成了白底白字 / 白底黄字。

## 3. 本轮做了什么：82 处可证明的无操作

审计工具 `scripts/_color-dedup-audit.mjs` 按「是否已在主题作用域内」给每处 hex 分类：

| 位置 | 出现次数 | 说明 |
|---|---:|---|
| 基础作用域 | 297 | 两主题都生效 → 换令牌会变语义 |
| **主题作用域内** | **183** | 已限定主题 → 换令牌可保值 |

再从 183 里筛出「值恰好等于**该主题**的令牌值」的：**65 处** —— 但其中 **43 处落在
令牌定义块内部**（首版的严重错误，见 §3.1），**真实可替换的是 22 处**。
加上 **17 处纯拼写**（`#ffffff` → `#fff`），共 **39 处**。

**关键的一步自我纠正**：脚本第一版在「一个值对应多个令牌」时**取了第一个**
（`#1e293b` 同时是 `--toast-bg` / `--surface-inset` / `--bar-track`；
`#c5d0e3` 同时是 `--border` / `--board-border` / `--input-border`）。
那不是去重，是**臆造语义**。改成**只处理唯一对应的值**后，从 98 处降到 65 处。

**改动的效果**（修复后实测）：

| 指标 | 改前 | 改后 |
|---|---:|---:|
| `style.css` hex 出现 | 480 | **458**（−22） |
| 全仓不同 hex 值 | 165 | **164**（−1，只消掉了 `#ffffff`） |
| `#ffffff` 残留 | 17 | **0** |

⚠ **这份收益比本文件初版写的（480→415、165→141）小得多**，因为初版把 43 处
令牌定义替换也算进了「去重」，而那 43 处是**把令牌改坏**、不是去重。更正后的
真实收益是：**22 处别名 + 17 处拼写，共 39 处**。
**颜色这条线的价值主要在「查清了为什么不能大改」（§4），不在这个数字上。**

## 3.1 ⚠ 事故：这次去重一度把整页变成黑底（已修复）

**第一版 `_color-dedup.mjs` 把令牌定义块本身也改了**，产出 43 处**自引用**：

```css
:root, html[data-theme="dark"] {
  --bg: var(--bg);      /* ← 循环引用 */
  --text: var(--text);
  --card: var(--card);
  ...
```

自定义属性引用自己构成**循环**，令牌在**计算值阶段失效**，所有 `var(--bg)` 消费者
回落成初始值 → 页面背景塌成默认黑、文字不可见。用户在电脑上打开就是这个现象。

**根因**：`_color-dedup.mjs` 用「选择器里含 `data-theme`」来划定作用域，
而 **`:root, html[data-theme="dark"]` 和 `html[data-theme="light"]` 这两个令牌定义块
本身就是 `data-theme` 作用域** —— 于是块内的 `--bg: #0b1220` 被当成普通声明替换了。

**为什么验证器没拦住**（这是更值得记的一点）：
`_verify-color-dedup.mjs` 从**改动前**的文件读令牌值来比对，于是
`#0b1220` 解析回 `#0b1220`「匹配」—— 它**从没检查新文件的令牌定义是否还是字面值**。
**保值检查对一个把令牌定义本身改坏的改动是盲的。**

**修复**：
- `scripts/_repair-token-cycles.mjs` 按「块 + 令牌名」从改动前版本还原 43 处；
  合法跨引用（`--input-bg: var(--bg2)`、`--input-border: var(--border)`）保留不动。
- `_color-dedup.mjs` 加硬约束：**任何定义自定义属性的行一律跳过**。
- `_verify-color-dedup.mjs` 加**循环检查**：扫描新文件里 `--x: var(--x)` 形式的自引用，
  非零即 FAIL。这条检查是本轮补上的，它就是当初该有的那条。

**修复后**：自引用 **0**；令牌块与改动前**逐行一致**；
`_verify-color-dedup.mjs HEAD~1` → `{changedLines:38, replacementsChecked:42,
mismatches:0, selfReferentialTokens:0}` **PASS**。
新增 `scripts/_theme-render-check.mjs`：直接读两个主题下 27 个令牌的解析值与
`body`/`.card` 的计算背景色，**空令牌或背景透明即 FAIL** —— 比截图快得多，
专门防这一类「令牌塌掉」的回归。两主题均 PASS，`pageErrors []`。
缓存 **v261 → v262**。

**顺带修掉一处 e2e 假失败**：修复后第一次跑 `browser-e2e.mjs` 超时退出 1，
卡在 `waitForFunction(() => !!window.vcfmMainApi)`。该文件里同一条件有 4 处，
都用的**默认 30 秒**，而同一文件里 `waitForSelector("#screen-main.active")` 给的是
**90 秒** —— 启动偶发超过 30 秒就会假红。**未改任何断言**，只把这 4 处对齐到 90 秒
（与同文件其它等待一致），随后两次连跑均**退出 0**。
⚠ 依据是「**无改动重跑也过**」：先确认是抖动，再动超时，不是把红改绿。

### 后续方案（**需要视觉复核，不要盲改**）

把基础规则改成**主题相关**、然后**删掉对应的浅色补丁**。这是真正的重构方向，
但它要求：

1. 给六族调色板各自定义**按角色的令牌**（如 `--danger-soft` / `--danger` / `--danger-strong`）；
2. 逐条把基础规则里的字面值换成令牌；
3. 逐条删掉 `日间模式全面补丁` 里因此变成多余的规则；
4. **两个主题、逐屏截图比对** —— 这一步无法自动化，`browser-e2e` 只验行为不验观感。

工作量与风险都明显高于本轮：它一次改动 300+ 处，且每一处都需要判断
「这个字面值在浅色下应该是什么」。所以本轮**只做能证明是恒等变换的那 82 处**。

## 5. 验收

### 5.1 静态证明（本轮的主要证据）

`scripts/_verify-color-dedup.mjs` 用 `git show HEAD:css/style.css` 取改动前的版本，
把每一行变化里的「颜色项」按顺序配对（`var(--token)` 与 `#hex` 都算一项），
**在该行所属的主题作用域里解析令牌值**，再与原来的字面值比较（`#fff` 与 `#ffffff`
先规范成 6 位再比）：

```
{"rev":"HEAD~1","changedLines":38,"replacementsChecked":42,"mismatches":0,"unpairedLines":0}
{"selfReferentialTokens":0}
PASS: every replacement is value-preserving and no token cycles exist
```

**42 项逐一比对、0 处不一致、0 处自引用** —— 即本次改动在渲染上是**恒等变换**。

⚠ **这个验证器当初没拦住 §3.1 的事故**，原因写在那一节：
它从**改动前**的文件读令牌值，所以对「把令牌定义本身改坏」是盲的。
本轮补上了 `selfReferentialTokens` 检查。**数字从 81/85 变成 38/42，正是因为
那 43 处错误替换被去掉了。**

> ⚠ 验证器第一版还报过 `changedLines: 8331`（全文都"变了"）。原因是
> **git 存的是 LF，工作区是 CRLF**，逐行比较时每行都因行尾不同而判为变化，
> 配对随即失去意义。归一化行尾后才得到正确的行数。
> **在 Windows 上做逐行对比，先归一化行尾。**

### 5.2 浏览器验收

`browser-e2e.mjs` 与双主题 `_ui-survey.mjs`（本轮给调研探针新增了 `[theme]` 参数，
`light` / `dark` / `both`）。见 §6 日志。

⚠ **本轮的浏览器验收是「防语法错误」而非「验保值」**：保值已由 §5.1 静态证明。
浏览器跑一遍是为了确认没有写坏 `var()`、没有 CSS 解析错误。
`#fff` → `var(--card)` 那 16 处**曾经**是我第一版的错误产物（按钮背景被当成卡片
背景），已在 §3 的唯一性约束下全部排除。

### 5.3 缓存

`sw.js` 的 `CACHE`、`index.html` 的 `CURRENT_CACHE`、三处 `?v=`、
`vcfm-sw-reloaded-v` 同步升 **v260 → v261**。
